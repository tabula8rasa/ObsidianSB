## 1. Основные понятия

| Понятие | Определение |
|---|---|
| **Tablespace** | Логический контейнер, которому принадлежат файлы данных и сегменты. |
| **Datafile** | Физический файл на диске (часто `.dbf`), содержащий блоки данных и extents разных сегментов. |
| **Segment** | Пространство, выделенное таблице, индексу или отдельной партиции; состоит из extents. |
| **Extent** | Набор последовательных блоков, выделенных одному сегменту целиком в пределах одного datafile. |
| **Data Block** | Минимальная логическая единица хранения Oracle; аналог PostgreSQL Page. Часто **8 КБ**, размер настраивается. |
| **Row / Row Piece** | Строка или её физическая часть, размещённая внутри блока. |

**Важно:** `.dbf` — это **datafile**, а не data block. Один файл содержит множество блоков.

## 2. Иерархия и размещение
![[Pasted image 20261018150404.png|800]]
```text
TABLESPACE (USERS)
├── DATAFILE users01.dbf
│   ├── EXTENT A → сегмент таблицы ORDERS
│   │   ├── BLOCK 1 (8 КБ)
│   │   ├── BLOCK 2 (8 КБ)
│   │   └── ...
│   └── EXTENT B → сегмент индекса ORDERS_IDX
│       ├── BLOCK 1 (8 КБ)
│       └── ...
└── DATAFILE users02.dbf
    └── EXTENT C → сегмент таблицы ORDERS
        ├── BLOCK 1 (8 КБ)
        └── ...
```

Две связанные иерархии:

- **Логическая:** `Tablespace → Segment → Extent → Data Block → Row`.
- **Физическое размещение:** `Tablespace → Datafile → Extent → Data Block`.

Сегмент может занимать несколько datafiles **одного tablespace**. Каждый extent целиком расположен **в одном datafile**. В одном datafile могут находиться extents разных сегментов.

## 3. Зачем нужен Extent

**Extent — единица выделения пространства сегменту.** Когда имеющегося места недостаточно, Oracle выделяет сегменту дополнительный extent.

Пример расчёта: при блоке **8 КБ** extent размером **1 МБ** содержит **128 блоков**. Это иллюстрация, а не фиксированный размер extent.

Такое выделение упрощает управление свободным пространством и уменьшает накладные расходы на его учёт.

## 4. Аналогия с PostgreSQL

| PostgreSQL | Oracle |
|---|---|
| Page | Data Block |
| Heap Tuple | Row / Row Piece |
| Файлы отношения | Datafiles и сегменты (другая организация) |
| Отдельного аналога extent нет | Extent |

- В PostgreSQL версии строк при `UPDATE` хранятся в heap; Oracle использует **UNDO** для восстановления предыдущих состояний блоков.
- Для адресации строки PostgreSQL использует `CTID`, Oracle — `ROWID`.

## 5. Связь с HWM

**HWM (High Water Mark)** — граница ранее использованного пространства **сегмента** (для партиционированной таблицы — соответствующего сегмента партиции).

- `DELETE` удаляет строки, но не снижает HWM.
- `TRUNCATE` сбрасывает HWM соответствующего сегмента.
- Full Table Scan ориентируется на HWM; пустые форматированные блоки ниже границы могут увеличивать объём чтения.

**Итог:** Oracle хранит строки в **Data Blocks**, выделяет пространство сегментам через **Extents**, а физически размещает всё в **Datafiles**, принадлежащих **Tablespace**.

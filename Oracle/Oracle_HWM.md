## Принцип
- **HWM (High Water Mark)** — граница между областью сегмента, уже использовавшейся для хранения данных, и областью, ещё не использовавшейся.
- При **Full Table Scan** Oracle не сканирует блоки выше HWM. Блоки ниже границы могут читаться даже после удаления из них всех строк.
- В сегментах с **ASSM** существует также **Low HWM**: неформатированные блоки между Low HWM и HWM можно пропускать по bitmap.

## Изменение HWM
- **Обычный INSERT** повторно использует свободное место в блоках; когда его недостаточно, область использования расширяется.
- **Direct-path INSERT (`APPEND`)** записывает данные выше текущего HWM, не используя обычный поиск свободного места ниже него.
- **DELETE** освобождает место для новых строк, но **не снижает HWM**.
- **TRUNCATE** сбрасывает HWM; это DDL с неявным COMMIT.
- **SHRINK SPACE** уплотняет сегмент и снижает HWM; **ALTER TABLE MOVE** создаёт новый сегмент с новой границей.

## Влияние на производительность
- **Польза:** Full Table Scan ограничен использованной областью, а не всеми выделенными сегменту блоками.
- **Проблема:** после массового `DELETE` под HWM остаются пустые блоки; Full Table Scan может выполнять лишний ввод-вывод.
- **ETL-ловушка:** повторяющиеся `INSERT /*+ APPEND */` и `DELETE` способны увеличивать HWM при небольшом текущем числе строк.
- **Индексный поиск** не сканирует все блоки таблицы до HWM и напрямую от этой границы не зависит.

## Отличие от PostgreSQL
- В PostgreSQL размер области сканирования определяется физическими страницами relation.
- После `DELETE` обе СУБД могут сохранять выделенное пространство, но в PostgreSQL дополнительно накапливаются **dead tuples**, которые очищает `VACUUM`.
- В Oracle пустые блоки ниже HWM не являются аналогом dead tuples: проблема связана с границей сканирования и использованием пространства, а не с хранением старых MVCC-версий.

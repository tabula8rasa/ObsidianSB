# Типы блокировок в базах данных

Здесь важно разделить две вещи:

- **режим блокировки** — что разрешено делать: `Shared`, `Exclusive`, `Update`;
- **уровень блокировки** — какой объём данных блокируется: строка, страница или таблица.

Некоторые названия, например `Update Lock`, `Bulk Update Lock` и `Key-Range Lock`, особенно характерны для Microsoft SQL Server.

---

## 1. Shared Lock — разделяемая блокировка

Используется при чтении данных.

Несколько транзакций могут одновременно установить `Shared Lock` на один ресурс и читать его. Но изменить ресурс в этот момент нельзя, потому что для изменения нужна эксклюзивная блокировка.

Пример:

```sql
SELECT balance
FROM accounts
WHERE id = 10;
```

Пока транзакция читает строку:

- другие транзакции тоже могут её читать;
- другие транзакции обычно не могут её изменить.

Условно:

```text
Транзакция 1: читает строку
Транзакция 2: читает эту же строку — разрешено
Транзакция 3: пытается изменить строку — ожидает
```

Обычно `Shared Lock` обозначают буквой `S`.

---

## 2. Exclusive Lock — эксклюзивная блокировка

Используется при изменении данных: `INSERT`, `UPDATE`, `DELETE`.

Только одна транзакция может владеть эксклюзивной блокировкой ресурса. Другие транзакции не могут установить на него несовместимые блокировки.

Пример:

```sql
UPDATE accounts
SET balance = balance - 100
WHERE id = 10;
```

Пока транзакция изменяет строку:

- другая транзакция не может её изменить;
- при классической блокировочной модели другая транзакция также не сможет прочитать её до снятия блокировки;
- при MVCC или snapshot isolation чтение старой версии может быть разрешено.

Обозначается `X`.

Эксклюзивная блокировка обычно удерживается до `COMMIT` или `ROLLBACK`.

---

## 3. Update Lock — блокировка намерения обновить

Используется, когда транзакция сначала читает данные, но затем собирается их изменить.

Она нужна для уменьшения риска взаимоблокировки.

Представим две транзакции:

```text
Транзакция 1 читает строку с Shared Lock
Транзакция 2 читает ту же строку с Shared Lock

После этого обе хотят получить Exclusive Lock.
```

Обе транзакции уже держат совместимые `Shared Lock`, но каждая ждёт, пока другая освободит блокировку. Может возникнуть deadlock.

`Update Lock` решает это так:

- читать строку другим транзакциям обычно можно;
- только одна транзакция может установить `Update Lock`;
- перед изменением `Update Lock` преобразуется в `Exclusive Lock`.

Обозначается `U`.

Пример SQL Server:

```sql
SELECT *
FROM accounts WITH (UPDLOCK)
WHERE id = 10;
```

Затем:

```sql
UPDATE accounts
SET balance = balance - 100
WHERE id = 10;
```

То есть `Update Lock` ещё не изменяет данные, а резервирует возможность последующего изменения.

## 4. Schema Lock — блокировка схемы

Защищает структуру объекта базы данных, а не конкретные значения строк.

Она нужна, чтобы таблицу нельзя было одновременно использовать и изменять её структуру несовместимым образом.

Например, транзакция выполняет:

```sql
SELECT *
FROM users;
```

В это время другая транзакция пытается выполнить:

```sql
ALTER TABLE users
DROP COLUMN email;
```

СУБД должна предотвратить ситуацию, когда запрос работает с колонкой, которая одновременно удаляется.

### Schema Stability Lock — `Sch-S`

Используется во время выполнения запросов.

Она означает:

```text
Структура объекта должна оставаться стабильной, пока выполняется запрос.
```

Несколько запросов могут одновременно удерживать `Sch-S`.

### Schema Modification Lock — `Sch-M`

Используется при изменении структуры:

```sql
ALTER TABLE
DROP TABLE
CREATE INDEX
TRUNCATE TABLE
```

`Sch-M` — очень строгая блокировка. Она обычно несовместима почти со всеми другими блокировками объекта.

---

## 5. Bulk Update Lock — блокировка массового обновления

Используется при массовой загрузке большого количества данных.

Например:

```sql
BULK INSERT
```

или при использовании специальных режимов массовой вставки.

Цель такой блокировки — повысить производительность массовой загрузки и уменьшить накладные расходы на блокирование каждой строки отдельно.

Пример:

```sql
BULK INSERT sales
FROM 'sales.csv';
```

В SQL Server такая блокировка обозначается `BU`.

Она может разрешать одновременные массовые вставки при определённых условиях, но блокировать обычные операции, которые могут конфликтовать с загрузкой.

Часто применяется вместе с табличной блокировкой:

```sql
INSERT INTO target_table WITH (TABLOCK)
SELECT *
FROM source_table;
```

Поведение зависит от СУБД, режима восстановления, индексов и параметров команды.

---

## 6. Key-Range Lock — блокировка диапазона ключей

Блокирует не только существующие строки, но и промежуток между значениями индексного ключа.

Используется для предотвращения фантомных чтений.

Допустим, транзакция выполняет:

```sql
SELECT *
FROM orders
WHERE amount BETWEEN 1000 AND 2000;
```

Она получила строки:

```text
1200
1500
1800
```

Пока первая транзакция работает, другая транзакция вставляет:

```text
1600
```

Если первая транзакция повторит запрос, она увидит новую строку. Это и есть фантомное чтение.

`Key-Range Lock` блокирует диапазон:

```text
от 1000 до 2000
```

Поэтому другая транзакция не сможет вставить в этот диапазон новый ключ до завершения первой транзакции.

Обычно такие блокировки применяются при уровне изоляции `SERIALIZABLE`.

Важно: для эффективной блокировки диапазона обычно требуется подходящий индекс.

## 7. Row-Level Lock — блокировка строки

Блокируется одна конкретная строка или небольшое число строк.

Пример:

```sql
UPDATE users
SET status = 'blocked'
WHERE id = 15;
```

В идеальном случае СУБД блокирует только строку с `id = 15`.

Преимущества:

- высокая параллельность;
- другие транзакции могут работать с остальными строками;
- удобно для систем с большим количеством одновременных запросов.

Недостатки:

- каждая блокировка требует памяти;
- при изменении тысяч или миллионов строк управление большим количеством блокировок становится дорогим;
- СУБД может выполнить эскалацию блокировки до страницы или таблицы.

Условно:

```text
Строка 14 — доступна
Строка 15 — заблокирована
Строка 16 — доступна
```

---

## 8. Page-Level Lock — блокировка страницы

Страница — фиксированный блок данных, в котором хранится несколько строк.

Например, в SQL Server стандартная страница данных имеет размер 8 КБ.

Если заблокирована страница, блокируются сразу все строки, расположенные на ней.

Пример:

```text
Страница 1:
строка 1
строка 2
строка 3
строка 4
```

Если СУБД заблокировала страницу из-за изменения строки 2, транзакции могут столкнуться с блокировкой и при работе со строками 1, 3 или 4.

Преимущества:

- меньше блокировок;
- меньше затрат памяти;
- удобно при изменении большого количества соседних строк.

Недостаток — более низкая параллельность по сравнению с блокировками строк.

---

## 9. Table-Level Lock — блокировка таблицы

Блокируется вся таблица.

Пример:

```sql
UPDATE products
SET price = price * 1.1;
```

Если изменяется большая часть таблицы, СУБД может решить, что дешевле заблокировать всю таблицу, чем создавать сотни тысяч блокировок строк.

Преимущества:

- мало накладных расходов;
- эффективно для массовых операций;
- проще управление блокировками.

Недостатки:

- сильно уменьшается параллельность;
- другие транзакции могут потерять возможность работать даже с независимыми строками таблицы.

Условно:

```text
Транзакция 1 заблокировала таблицу users
Транзакция 2 хочет изменить строку id = 100 — ожидает
Транзакция 3 хочет изменить строку id = 500 — тоже ожидает
```

## Как блокировки связаны между собой

Например, запрос:

```sql
UPDATE users
SET balance = 500
WHERE id = 10;
```

может установить:

```text
Exclusive Lock
на уровне строки
```

То есть:

- `Exclusive` — режим блокировки;
- `Row-Level` — уровень блокировки.

Другой запрос может получить:

```text
Shared Lock
на уровне страницы
```

А массовое изменение:

```text
Exclusive Lock
на уровне таблицы
```

---

## Краткая таблица

| Блокировка | Для чего используется |
|---|---|
| `Shared Lock` | Чтение данных |
| `Exclusive Lock` | Изменение данных |
| `Update Lock` | Чтение с намерением последующего изменения |
| `Schema Lock` | Защита структуры таблицы или другого объекта |
| `Bulk Update Lock` | Массовая загрузка данных |
| `Key-Range Lock` | Защита диапазона индексных ключей от вставок |
| `Row-Level Lock` | Блокировка отдельной строки |
| `Page-Level Lock` | Блокировка группы строк на странице |
| `Table-Level Lock` | Блокировка всей таблицы |

---

## Главное правило

```text
S — читаю
U — собираюсь обновить
X — изменяю

Row / Page / Table — какой объём данных заблокирован
```

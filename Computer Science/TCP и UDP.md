**TCP** и **UDP** — транспортные протоколы, работающие поверх IP. Они обеспечивают передачу данных между приложениями и используют номера портов для определения отправителя и получателя.

Пример адреса приложения:

```text
192.168.1.10:443
```

Где:

- `192.168.1.10` — IP-адрес устройства;
    
- `443` — номер порта приложения.
    

---

# TCP

**TCP — Transmission Control Protocol** — протокол с установлением соединения и гарантированной доставкой данных.

Перед передачей данных TCP устанавливает соединение между клиентом и сервером.

## Установка соединения

Используется механизм **Three-Way Handshake**:

```text
Клиент                         Сервер

SYN          ───────────────────►
             ◄─────────────────── SYN-ACK
ACK          ───────────────────►
```

1. Клиент отправляет `SYN`.
    
2. Сервер отвечает `SYN-ACK`.
    
3. Клиент подтверждает соединение пакетом `ACK`.
    

После этого начинается передача данных.

---

## Основные свойства TCP

TCP обеспечивает:

- гарантированную доставку данных;
    
- сохранение порядка;
    
- повторную отправку потерянных сегментов;
    
- обнаружение ошибок;
    
- контроль потока;
    
- контроль перегрузки сети;
    
- двустороннее соединение.
    

Если часть данных потеряется, TCP обнаружит это и отправит её повторно.

```text
Отправлено: 1, 2, 3, 4

Получено:   1, 2, 4

TCP повторно отправит сегмент 3.
```

Приложение получает данные в правильном порядке:

```text
1, 2, 3, 4
```

Даже если отдельные сегменты пришли в другой последовательности.

---

## TCP — потоковый протокол

TCP передаёт не отдельные сообщения, а непрерывный поток байтов.

Например, приложение отправило:

```text
HELLO
WORLD
```

Получатель может прочитать данные как:

```text
HELLOWORLD
```

или частями:

```text
HEL
LOWOR
LD
```

Границы сообщений TCP не сохраняет. Приложение должно самостоятельно определять их, например через:

- длину сообщения;
    
- разделитель;
    
- собственный формат протокола.
    

---

## Где используется TCP

TCP подходит для случаев, когда важны целостность и порядок данных:

- HTTP и HTTPS;
    
- SSH;
    
- FTP;
    
- SMTP;
    
- IMAP;
    
- подключение к базам данных;
    
- передача файлов;
    
- API-запросы.

# UDP

**UDP — User Datagram Protocol** — протокол без предварительного установления соединения.

Отправитель передаёт отдельные сообщения — **датаграммы** — и не ожидает подтверждения доставки.

```text
Клиент                         Сервер

Датаграмма 1 ──────────────────►
Датаграмма 2 ──────────────────►
Датаграмма 3 ──────────────────►
```

Перед отправкой не выполняется handshake.

---

## Основные свойства UDP

UDP:

- не устанавливает соединение;
    
- не гарантирует доставку;
    
- не гарантирует порядок;
    
- не выполняет повторную отправку;
    
- не имеет встроенного контроля потока;
    
- не имеет встроенного контроля перегрузки;
    
- сохраняет границы сообщений;
    
- имеет небольшой заголовок;
    
- создаёт меньше накладных расходов.
    

Если датаграмма потерялась, UDP самостоятельно не будет её восстанавливать.

```text
Отправлено: 1, 2, 3, 4

Получено:   1, 3, 4
```

Датаграмма `2` будет потеряна, если приложение само не реализует повторную отправку.

---

## UDP сохраняет границы сообщений

Каждый вызов отправки создаёт отдельную датаграмму.

```text
Отправлено:
1. HELLO
2. WORLD
```

Получатель получает два отдельных сообщения:

```text
HELLO
WORLD
```

UDP не объединяет их в единый поток байтов.

---

## Где используется UDP

UDP подходит для систем, где скорость и небольшая задержка важнее гарантированной доставки:

- онлайн-игры;
    
- голосовая связь;
    
- видеозвонки;
    
- потоковое вещание;
    
- DNS;
    
- DHCP;
    
- NTP;
    
- телеметрия;
    
- обнаружение устройств в сети.
    

В голосовом звонке повторная отправка старого аудиопакета часто бесполезна: лучше потерять небольшой фрагмент, чем увеличить задержку.

# Сравнение TCP и UDP

|Характеристика|TCP|UDP|
|---|---|---|
|Установка соединения|Да|Нет|
|Гарантия доставки|Да|Нет|
|Сохранение порядка|Да|Нет|
|Повторная отправка|Да|Нет|
|Контроль потока|Да|Нет|
|Контроль перегрузки|Да|Нет|
|Границы сообщений|Не сохраняются|Сохраняются|
|Заголовок|Минимум 20 байт|8 байт|
|Накладные расходы|Выше|Ниже|
|Задержка|Обычно выше|Обычно ниже|
|Тип передачи|Поток байтов|Датаграммы|

# Порты

TCP и UDP используют номера портов от `0` до `65535`.

Одинаковый номер TCP- и UDP-порта может использоваться разными приложениями, потому что это разные пространства портов.

Например:

```text
TCP 53
UDP 53
```

Это разные транспортные endpoints.

Диапазоны портов:

|Диапазон|Назначение|
|---|---|
|`0–1023`|Системные и общеизвестные порты|
|`1024–49151`|Зарегистрированные порты|
|`49152–65535`|Динамические и временные порты|

Примеры:

|Протокол приложения|Порт|Транспорт|
|---|--:|---|
|HTTP|80|TCP|
|HTTPS|443|TCP|
|SSH|22|TCP|
|DNS|53|UDP и TCP|
|NTP|123|UDP|

# Заголовок UDP

UDP имеет простой заголовок размером 8 байт:

```text
+---------------------+
| Source Port         |
+---------------------+
| Destination Port    |
+---------------------+
| Length              |
+---------------------+
| Checksum            |
+---------------------+
```

Он содержит:

- порт отправителя;
    
- порт получателя;
    
- длину датаграммы;
    
- контрольную сумму.
    

---

# Заголовок TCP

Заголовок TCP содержит больше служебной информации:

- source port;
    
- destination port;
    
- sequence number;
    
- acknowledgment number;
    
- flags;
    
- window size;
    
- checksum;
    
- дополнительные options.
    

Основные флаги TCP:

|Флаг|Назначение|
|---|---|
|`SYN`|Установка соединения|
|`ACK`|Подтверждение получения|
|`FIN`|Корректное завершение соединения|
|`RST`|Немедленный сброс соединения|
|`PSH`|Передача данных приложению без задержки|

---

# Последовательность и подтверждения TCP

TCP нумерует передаваемые байты с помощью `Sequence Number`.

Получатель подтверждает данные с помощью `Acknowledgment Number`.

```text
Отправитель                    Получатель

SEQ = 100, данные 50 байт ─────►
             ◄────────────────── ACK = 150
```

`ACK = 150` означает, что получатель ожидает байт с номером `150`, а предыдущие байты уже получены.

---

# Контроль потока TCP

TCP не позволяет отправителю передавать данные быстрее, чем получатель способен их обрабатывать.

Получатель сообщает доступный размер буфера через **receive window**:

```text
Window Size
```

Если буфер заполнен, отправитель временно уменьшает скорость или останавливает передачу.

---

# Контроль перегрузки TCP

TCP также учитывает состояние сети.

Если обнаруживаются потери пакетов или рост задержки, протокол уменьшает скорость передачи. Это помогает не перегружать маршрутизаторы и сетевые каналы.

Контроль потока защищает получателя, а контроль перегрузки — сеть.

---

# Важный нюанс

UDP не всегда быстрее TCP.

UDP имеет меньше встроенных механизмов, но итоговая производительность зависит от:

- качества сети;
    
- размера сообщений;
    
- количества потерь;
    
- реализации приложения;
    
- необходимости повторной доставки;
    
- шифрования;
    
- используемого прикладного протокола.
    

Если поверх UDP самостоятельно реализовать подтверждения, порядок, повторные отправки и контроль перегрузки, сложность может приблизиться к TCP.

# QUIC

**QUIC** — современный транспортный протокол, работающий поверх UDP.

Он самостоятельно реализует:

- надёжную доставку;
    
- контроль перегрузки;
    
- шифрование;
    
- управление соединением;
    
- параллельные потоки данных.
    

QUIC используется в HTTP/3.

UDP в этом случае выступает как основа, а механизмы надёжности реализуются внутри QUIC.

---

# Кратко

**TCP выбирают, когда важны:**

- доставка всех данных;
    
- правильный порядок;
    
- целостность;
    
- надёжное соединение.
    

**UDP выбирают, когда важны:**

- минимальная задержка;
    
- небольшие накладные расходы;
    
- передача отдельных сообщений;
    
- допустима потеря части данных.
    

```text
TCP — надёжность и порядок.

UDP — скорость, простота и минимальная задержка.
```

# Урок 08. Range и Conditional Requests: частичное чтение S3

> [!abstract] Цель урока
> Научиться запрашивать отдельные диапазоны байтов объекта и выполнять чтение только при выполнении условий. Понять применение этих механизмов для больших файлов, кеширования и защиты от чтения изменившихся данных.

**Предварительные знания:** уроки 1–7; `GetObject`, `HeadObject`, `ETag`, HTTP-заголовки.  
**Практическая среда:** локальный RustFS, AWS CLI, терминал `fish`.  
**Критерий завершения:** прочитан диапазон байтов; выполнен запрос с `If-Match`; объяснены ответы `206`, `304`, `412`.

---

## 1. Range: чтение части объекта

**Range request** — запрос `GetObject`, ограничивающий передаваемое содержимое указанным диапазоном байтов.

Синтаксис HTTP-заголовка:

```http
Range: bytes=10-15
```

Диапазон **включает обе границы**: будут прочитаны байты с индексами `10, 11, 12, 13, 14, 15`, всего **6 байтов**. Индексация начинается с нуля.

Поддерживаются формы `bytes=N-M`, `bytes=N-` (до конца объекта) и `bytes=-N` (последние N байтов). AWS S3 поддерживает **один диапазон на один GET-запрос**.

Важно: частичное **чтение** не означает возможность изменить выбранный участок существующего объекта на месте. Для обновления содержимого используются операции записи объекта.

---

## 2. Как сервер отвечает на Range

При успешном частичном чтении HTTP-ответ содержит:

- **`206 Partial Content`** — возвращена часть содержимого.
- **`Content-Range`** — фактически выданный диапазон и полный размер объекта.
- **`Content-Length`** — размер переданной части, а не всего объекта.

Для объекта длиной `1000` байтов и запроса `bytes=10-15`:

```http
HTTP/1.1 206 Partial Content
Content-Range: bytes 10-15/1000
Content-Length: 6
```

Если указанный диапазон не может быть удовлетворён, сервер возвращает `416 Range Not Satisfiable` (для соответствующего сценария HTTP Range).

**Архитектурный смысл:** клиент получает нужные байты без передачи всего объекта по сети. Способ чтения данных с физических носителей остаётся внутренней деталью хранилища.

---

## 3. Связь HEAD, Range и больших файлов

Перед частичным скачиванием клиент может выполнить `HeadObject`:

1. Получить `ContentLength` — общий размер.
2. Получить `ETag` — значение для условного запроса.
3. Разбить объект на диапазоны.
4. Прочитать их последовательными или параллельными GET-запросами.
5. Собрать ответ в исходном порядке и проверить корректность результата.

Это используется при возобновлении скачивания, параллельном чтении крупных объектов и доставке видео.

**Не путай:** скачивание диапазона через GET и **Multipart Upload** — разные механизмы. Первый управляет чтением; второй — записью большого объекта частями (урок 9).

---

## 4. Conditional Requests: запросы с предусловиями

**Conditional request** — запрос, который сервер выполняет с учётом состояния объекта.

- **`If-Match: <ETag>`** — вернуть объект, если текущий ETag совпадает с переданным; при несовпадении — `412 Precondition Failed`.
- **`If-None-Match: <ETag>`** — вернуть объект, если ETag отличается; при совпадении для GET — `304 Not Modified` без тела объекта.
- **`If-Unmodified-Since`** — вернуть объект, только если он не изменялся после заданного времени; при нарушении условия — `412`.
- **`If-Modified-Since`** — вернуть объект, только если он изменялся после заданного времени; иначе — `304`.

Условия по ETag полезны, когда клиент сначала получает сведения через HEAD, а затем читает объект. **ETag — не универсальная контрольная сумма файла и не замена `versionId`.**

---

## 5. Зачем сочетать Range и If-Match

Представим, что backend читает большой объект по частям. Пока он скачивает первую половину, другой клиент записывает новое содержимое по тому же ключу.

Без проверки состояния приложение рискует собрать результат из диапазонов, относящихся к разным состояниям объекта.

```text
HEAD → получить ETag
  ↓
GET range 1 + If-Match: ETag
  ↓
GET range 2 + If-Match: ETag
  ↓
Собрать данные, только если оба запроса успешны
```

Если объект изменился и условие перестало выполняться, сервер возвращает ошибку предусловия; клиент должен заново получить актуальное состояние и решить, нужно ли повторить скачивание.

Для неизменяемого чтения конкретной версии при включённом versioning приложение может указывать `versionId`. Версионирование изучим в уроке 11.

## 6. Практика: диапазон и условное чтение

Используй бакет `s3-course-lesson1` и endpoint `http://127.0.0.1:9000`.

**1. Запиши объект с известным содержимым:**

```fish
printf '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ\n' > lesson08.txt
aws --endpoint-url http://127.0.0.1:9000 s3api put-object \
  --bucket s3-course-lesson1 --key lesson08/data.txt \
  --body lesson08.txt
```

**2. Прочитай байты с 10-го по 15-й:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api get-object \
  --bucket s3-course-lesson1 --key lesson08/data.txt \
  --range bytes=10-15 part08.txt

printf 'ABCDEF' > expected08.txt
cmp part08.txt expected08.txt
```

`cmp` должен завершиться без различий. В ответе `GetObject` найди `ContentRange` и `ContentLength`.

**3. Получи ETag и повтори чтение с условием:**

```fish
set etag (aws --endpoint-url http://127.0.0.1:9000 s3api head-object \
  --bucket s3-course-lesson1 --key lesson08/data.txt \
  --query ETag --output text)

aws --endpoint-url http://127.0.0.1:9000 s3api get-object \
  --bucket s3-course-lesson1 --key lesson08/data.txt \
  --if-match $etag --range bytes=10-15 matched08.txt
```

**4. Проверь условие неизменности:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api get-object \
  --bucket s3-course-lesson1 --key lesson08/data.txt \
  --if-none-match $etag unchanged08.txt
```

**Ожидаемый результат:** последний запрос получает `304 Not Modified`; AWS CLI отображает его как ошибку операции без скачивания содержимого. Это успешная проверка условия, а не неисправность хранилища.

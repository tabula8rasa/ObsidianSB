# Урок 07. CopyObject, массовое удаление и перемещение

> [!abstract] Цель урока
> Понять операции копирования и удаления объектов, определить, почему привычные перемещение и переименование не являются одной атомарной операцией в обычном S3-бакете, и освоить пакетное удаление.

**Предварительные знания:** уроки 1–6; bucket, key, `PutObject`, `HeadObject`, метаданные.  
**Практическая среда:** локальный RustFS, AWS CLI, терминал `fish`.  
**Критерий завершения:** объект скопирован под новым ключом, исходный удалён, выполнено пакетное удаление; различаются логические и физические операции.

---

## 1. CopyObject: создание нового объекта из существующего

**`CopyObject`** — операция S3 API, которая создаёт объект назначения на основе объекта-источника.

Клиент задаёт два идентификатора:

```text
Source:      bucket-A / documents/report.pdf
Destination: bucket-B / archive/report.pdf
```

Копирование возможно в пределах бакета и между бакетами при наличии необходимых прав. В AWS S3 оно может выполняться и между регионами с соблюдением требований соответствующих endpoint и разрешений.

**В обычном AWS S3 `CopyObject` копирует объект размером до 5 ГиБ одним запросом** (предельный размер указан как 5 GB в документации AWS). Для объектов большего размера используется multipart copy — копирование частей с последующей сборкой (урок 9).

> [!important] Копирование не создаёт ссылку
> Источник и назначение — два отдельных объекта с собственными ключами. Последующее изменение или удаление источника не является командой изменить либо удалить копию.

---

## 2. Что переносится при копировании

На логическом уровне операция выполняет следующие шаги:

1. Проверить доступ к исходному объекту и возможность записи назначения.
2. Прочитать необходимые данные и атрибуты источника внутри сервиса хранения.
3. Создать объект назначения с указанным ключом и настройками копирования.
4. Вернуть результат операции клиенту.

В AWS S3 по умолчанию копируются метаданные и теги, но часть атрибутов может определяться настройками бакета назначения или параметрами запроса.

- `MetadataDirective=COPY` — сохранить пользовательские метаданные и поддерживаемые свойства источника.
- `MetadataDirective=REPLACE` — задать новый набор метаданных.
- Настройки доступа и шифрования назначения требуют отдельного внимания; нельзя считать все свойства источника неизменными.

**S3 API не требует скачивать объект на backend и снова загружать его** для копирования внутри одной S3-системы: клиент отправляет команду копирования.

---

## 3. Переименование и перемещение

Для **обычных S3-бакетов** переименование выполняется через последовательность:

```text
CopyObject(old_key → new_key)
       ↓ успешное копирование
DeleteObject(old_key)
```

Перемещение между бакетами строится по тому же принципу. **Общей транзакции между двумя действиями нет.**

- После копирования и до удаления существуют оба ключа.
- Если копирование не удалось, удалять исходный объект нельзя.
- Если удаление не удалось, останутся две копии.
- Параллельная запись в исходный ключ требует контроля согласованности на уровне приложения.

Для специальных **directory buckets** в AWS S3 Express One Zone существует отдельная операция `RenameObject`. Это не универсальная возможность S3-совместимых хранилищ и не модель нашей лаборатории.

---

## 4. DeleteObject: логическое удаление

**`DeleteObject`** адресует один ключ или конкретную версию объекта.

Поведение в AWS S3 зависит от конфигурации бакета:

- **Без версионирования:** текущий объект удаляется.
- **С включённым версионированием:** обычный DELETE добавляет *delete marker*, скрывающий прежнюю текущую версию; прежние версии сохраняются.
- **С указанием `versionId`:** удаляется выбранная версия при наличии необходимых прав и отсутствии запрещающих ограничений.

Успешный DELETE не означает подтверждённого физического стирания байтов на всех носителях. S3 описывает результат API, а не внутренний алгоритм освобождения диска.

---

## 5. DeleteObjects: массовое удаление

**`DeleteObjects`** — одна операция API для удаления набора ключей. В обычном AWS S3 один запрос содержит **до 1000 объектов**.

В отличие от `DeleteObject`, клиент передаёт список ключей (при необходимости — версий). Ответ может содержать сведения об удалённых элементах и ошибки для отдельных элементов.

**Пакетное удаление не является транзакцией «всё или ничего».** При обработке результата нужно проверить индивидуальные ошибки, а не только HTTP-статус ответа.

Для удаления больших наборов backend разбивает список на партии и учитывает успешные, ошибочные и повторные попытки. Версионирование и ограничения Object Lock могут изменить итог удаления.

## 6. Практика: копирование, «переименование», пакетное удаление

Используй `s3-course-lesson1` и локальный endpoint. Пример рассчитан на бакет без включённого версионирования.

**1. Создай исходный объект и копию:**

```fish
printf 'Lesson 07\n' > lesson07.txt
aws --endpoint-url http://127.0.0.1:9000 s3api put-object \
  --bucket s3-course-lesson1 --key lesson07/source.txt --body lesson07.txt

aws --endpoint-url http://127.0.0.1:9000 s3api copy-object \
  --copy-source s3-course-lesson1/lesson07/source.txt \
  --bucket s3-course-lesson1 --key lesson07/archive.txt
```

**2. Проверь назначение и удали источник:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api head-object \
  --bucket s3-course-lesson1 --key lesson07/archive.txt

aws --endpoint-url http://127.0.0.1:9000 s3api delete-object \
  --bucket s3-course-lesson1 --key lesson07/source.txt
```

**3. Подготовь ещё один объект и удали два объекта одним запросом:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api put-object \
  --bucket s3-course-lesson1 --key lesson07/temporary.txt --body lesson07.txt

aws --endpoint-url http://127.0.0.1:9000 s3api delete-objects \
  --bucket s3-course-lesson1 \
  --delete '{"Objects":[{"Key":"lesson07/archive.txt"},{"Key":"lesson07/temporary.txt"}],"Quiet":false}'
```

**Критерий успеха:** операция копирования создала второй ключ, удаление исходного не удалило копию, ответ `DeleteObjects` не содержит записей в `Errors`.

## 7. Самостоятельные задания

1. Почему backend не должен удалять источник сразу после отправки запроса `CopyObject`, до проверки результата?
2. При перемещении файла процесс упал между копированием и удалением. Опиши состояние данных и безопасный алгоритм повторного выполнения.
3. В бакете включено версионирование. Почему обычный DELETE и окончательное удаление всех версий — разные задачи?

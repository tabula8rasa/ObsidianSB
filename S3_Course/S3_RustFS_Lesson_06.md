# Урок 06. Метаданные объектов: системные, пользовательские, теги

> [!abstract] Цель урока
> Разделить содержимое объекта и сведения о нём. Понять назначение системных и пользовательских метаданных, отличие тегов и способы изменения этих атрибутов через S3 API.

**Предварительные знания:** уроки 1–5; `PutObject`, `HeadObject`, `GetObject`, ключи объектов.  
**Практическая среда:** локальный RustFS, AWS CLI, терминал `fish`.  
**Критерий завершения:** объект записан с метаданными; сведения прочитаны через HEAD; теги изменены без перезаписи содержимого.

---

## 1. Что такое метаданные объекта

**Метаданные (metadata)** — атрибуты объекта, которые описывают его содержимое, состояние и правила обработки. Они передаются и хранятся отдельно от последовательности байтов объекта.

В модели S3 различают:

- **Системные метаданные** — стандартные поля, часть которых вычисляет хранилище, а часть задаёт клиент.
- **Пользовательские метаданные** — пары `имя → значение`, передаваемые приложением.
- **Теги объекта** — отдельный набор пар `ключ → значение`, управляемый специальными операциями API.

**Архитектурный смысл:** объектное хранилище отвечает за байты и их S3-атрибуты. Бизнес-сущность приложения («файл пользователя», «документ заказа») не возникает в S3 автоматически.

---

## 2. Системные метаданные

Основные поля:

- **`Content-Type`** — MIME-тип содержимого, например `application/pdf`; задаётся клиентом или определяется инструментом загрузки. S3 не обязан анализировать содержимое файла для проверки типа.
- **`Content-Length`** — количество байтов тела объекта; определяется объёмом записанных данных.
- **`Last-Modified`** — время последнего изменения объекта, установленное хранилищем.
- **`ETag`** — идентификатор состояния представления объекта, используемый в условных запросах. **ETag не всегда является MD5-хешем содержимого**.

`HeadObject` возвращает сведения об объекте без его тела. `GetObject` возвращает тело и заголовки с метаданными.

> [!important] Не путай
> `Content-Type` описывает ожидаемую интерпретацию байтов, но не меняет их. `Content-Length` не включает размер пользовательских метаданных.

---

## 3. Пользовательские метаданные

**User-defined metadata** — небольшие текстовые атрибуты, которые приложение связывает с объектом при его записи.

В HTTP API их имена имеют префикс `x-amz-meta-`. Например, заголовок `x-amz-meta-source: course` обозначает пользовательский атрибут `source=course`.

В AWS CLI метаданные передаются параметром `--metadata`; `HeadObject` возвращает их в поле `Metadata`.

Важные свойства:

- Пользовательские метаданные относятся к конкретному объекту (или его версии).
- В обычной модели S3 их нельзя изменить отдельной командой «обновить поле»: нужно переписать объект либо выполнить копирование с заменой метаданных.
- `ListObjectsV2` **не фильтрует объекты** по произвольным пользовательским метаданным.

Следовательно, метаданные не заменяют прикладной поисковый индекс.

---

## 4. Теги объектов

**Object tags** — набор пар `Key/Value`, хранящийся отдельно от пользовательских метаданных. В обычных бакетах AWS S3 у объекта может быть до **10 тегов**.

- `PutObjectTagging` — заменить набор тегов объекта.
- `GetObjectTagging` — прочитать теги.
- `DeleteObjectTagging` — удалить набор тегов.

В AWS теги применяются в политиках доступа, правилах жизненного цикла и учёте затрат. **`HeadObject` не возвращает полный набор тегов**: для этого используется `GetObjectTagging`.

Главное отличие: **теги можно изменять, не загружая содержимое заново**. Пользовательские метаданные требуют операции записи или копирования объекта.

---

## 5. Где хранить прикладные атрибуты

Рассмотрим архитектуру сервиса хранения документов:

```text
PostgreSQL: file_id, owner_id, filename, bucket, key, status
S3:         key → bytes + Content-Type + metadata + tags
```

- **База приложения** хранит владельца, отображаемое имя, связи между сущностями и поля для поиска.
- **S3** хранит объект и атрибуты, нужные для его доставки и управления хранением.
- **Связь** устанавливается по сохранённым в БД `bucket + key` (при необходимости — `versionId`).

Это разделение позволяет переименовать файл в интерфейсе без изменения S3-ключа и не выполнять полный листинг бакета ради поиска по пользовательскому названию.

## 6. Практика: запись, чтение и изменение атрибутов

Используй бакет `s3-course-lesson1`, credentials из предыдущих уроков и endpoint `http://127.0.0.1:9000`.

**1. Загрузи объект с типом и пользовательскими метаданными:**

```fish
printf 'Metadata lesson 06\n' > lesson06.txt
aws --endpoint-url http://127.0.0.1:9000 s3api put-object \
  --bucket s3-course-lesson1 --key lesson06/document.txt \
  --body lesson06.txt --content-type text/plain \
  --metadata source=course,stage=draft
```

**2. Прочитай метаданные без скачивания файла:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api head-object \
  --bucket s3-course-lesson1 --key lesson06/document.txt \
  --query '{Size:ContentLength,Type:ContentType,Metadata:Metadata}'
```

**3. Назначь тег и проверь его отдельным запросом:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api put-object-tagging \
  --bucket s3-course-lesson1 --key lesson06/document.txt \
  --tagging '{"TagSet":[{"Key":"stage","Value":"reviewed"}]}'

aws --endpoint-url http://127.0.0.1:9000 s3api get-object-tagging \
  --bucket s3-course-lesson1 --key lesson06/document.txt
```

**4. Замени пользовательские метаданные копированием на тот же ключ:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api copy-object \
  --copy-source s3-course-lesson1/lesson06/document.txt \
  --bucket s3-course-lesson1 --key lesson06/document.txt \
  --metadata-directive REPLACE --content-type text/plain \
  --metadata source=course,stage=reviewed
```

Повтори `HeadObject`. Сравни поле `Metadata` с предыдущим ответом; затем проверь теги через `GetObjectTagging`.

**Критерий успеха:** поле `stage` в `Metadata` изменилось после копирования, а набор тегов читается отдельной операцией.

# Telegram Bot HITL — спецификация MVP

## Назначение

Получить запрос от HITL, показать его пользователю и передать ответ обратно. Бот не хранит статусы ожидания и не управляет Codex.

## Интерфейсы

- `POST /internal/messages` — получает от MCP `request_id`, `type`, `title`, `description`; возвращает `message_id`.
- Telegram Bot API `getUpdates` — Long Polling для новых событий.
- `POST /internal/answer` — бот передаёт MCP `request_id` и `answer`; получает `accepted: true/false`.

## Функции

- **`send_message(...)`** — собирает текст и кнопки по типу запроса, отправляет сообщение, возвращает `message_id`.
- **`poll_updates()`** — получает события Telegram и передаёт их обработчику.
- **`handle_update(update)`** — проверяет разрешённого пользователя; извлекает `request_id` из кнопки либо из сообщения, на которое ответили; формирует ответ.
- **`send_answer_to_mcp(...)`** — отправляет ответ HITL и сообщает пользователю, если запрос уже неактивен или доставка не удалась.

## Типы запросов

| Тип | Интерфейс пользователя | Результат |
|---|---|---|
| `approval` | «Подтвердить» / «Отклонить» | `approved` / `rejected` |
| `question` | Текстовый ответ на сообщение | `answered` + `answer` |
| `manual_action` | «Готово» / «Не могу» | `completed` / `unable` |

## Ограничения

- Python, FastAPI, Telegram Bot API, отдельный Docker-контейнер.
- Без БД и webhook; один процесс Long Polling.
- Идентификатор запроса передаётся в `callback_data` либо тексте исходного сообщения для `reply_to_message`.
- Принимает ответы только от `TELEGRAM_ALLOWED_USER_ID`.
- Внутренние вызовы защищены `INTERNAL_API_TOKEN`.
- Настройки: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_ALLOWED_USER_ID`, `HITL_API_URL`, `INTERNAL_API_TOKEN`.

**Статус:** проектный контракт, без реализации.


## Дополнения к сообщениям и обработке ответов

- Сообщение включает имя агента (`agent_name`) и его роль (`agent_role`), когда эти данные доступны. Способ их получения и передачи пока не определён; бот не должен придумывать отсутствующие имя или роль.
- Для `question` принимается только текстовый прямой ответ (`reply_to_message`) на соответствующее сообщение бота. Обычный текст без такой привязки не считается ответом на запрос.
- Для `approval` и `manual_action` принимаются только соответствующие нажатия кнопок. Текстовый ответ разрешённого пользователя на такое сообщение игнорируется и удаляется из чата; в MCP он не передаётся и запрос не завершает.
- Первый валидный ответ окончательно принимается сервером MCP. Завершённые или отменённые запросы не открываются повторно; бот не создаёт новое ожидание при повторном ответе на старое сообщение.
- После получения `accepted: true` от MCP бот удаляет inline-кнопки из соответствующего сообщения Telegram. До подтверждения MCP кнопки не удаляются как признак принятого ответа.
- Восстановление доставки и неоднозначные результаты доставки отложены за рамки текущего MVP; существующее уведомление пользователя о неудачной доставке или неактивном запросе сохраняется.

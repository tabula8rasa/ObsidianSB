# Jira: термины и рабочий процесс

**Jira** — инструмент управления задачами, а **не методология**. Поддерживает Scrum, Kanban и процессы компании. В Jira Cloud встречаются обе пары названий: **Project / Space** (пространство) и **Issue / Work item** (задача).

## 1. Структура задач

```text
Project / Space
└── Epic
    └── Story / Task / Bug
        └── Subtask
```

| Термин | Значение |
|---|---|
| **Epic** | Крупная функциональность, объединяющая задачи |
| **Story** | Требование с точки зрения пользователя и его ценности |
| **Task** | Техническая или организационная работа |
| **Bug** | Ошибка в существующем поведении |
| **Subtask** | Часть родительской задачи; самостоятельно не существует |
| **Initiative** | Бизнес-цель над несколькими эпиками; зависит от конфигурации Jira |
| **Spike** | Исследование неопределённости; результат — вывод, оценка или прототип |

**Идентификатор:** `DATA-842` = ключ пространства + номер задачи. Его используют в ветках Git, коммитах, PR и переписке. Уровни выше Epic и тип Spike могут требовать настройки.

**Формула Story:** «Как *роль*, я хочу *действие*, чтобы *ценность*». 

**Acceptance Criteria** — проверяемые условия приёмки конкретной задачи, а не описание способа реализации.

## 2. Поля, статусы и связи

| Поле | Для чего |
|---|---|
| **Summary / Description** | Краткий результат / контекст и требования |
| **Assignee / Reporter** | Исполнитель / инициатор |
| **Priority / Due Date** | Приоритет / срок |
| **Status / Resolution** | Где задача сейчас / почему закрыта (`Done`, `Duplicate`, `Won't Do`) |
| **Labels / Component** | Метки / часть продукта |
| **Fix Version / Affects Version** | Версия исправления / версия, где возникла ошибка |
| **Story Points** | Относительная сложность, объём и неопределённость; **не часы** |
| **Original / Remaining / Time Spent** | Первичная оценка / остаток / фактическое время |
| **Sprint / Watchers** | Принадлежность к спринту / наблюдатели |

- **Workflow** — допустимый путь между статусами; **Transition** — конкретный разрешённый переход.
- **Parent** — отношение «родитель → дочерняя задача». **Link** — связь между задачами: `blocks`, `is blocked by`, `duplicates`, `relates to`.
- **Backlog** — упорядоченная очередь будущих работ. **Board** — отображение задач по фильтру, а не отдельное место их хранения; одна задача может быть на нескольких досках.

## 3. Как движется задача

```text
Backlog → Ready → In Progress → Code Review → Testing → Done
                            ↑                 |
                            └── доработка ───┘
```

1. Создать задачу с понятным результатом и критериями приёмки.
2. Уточнить детали, оценить и установить приоритет в Backlog.
3. Взять задачу в работу, назначить Assignee, связать зависимости.
4. Разработать решение, выполнить code review и тестирование.
5. Закрыть после выполнения критериев готовности; при ошибках вернуть в работу.

**Scrum Board:** задачи выбирают в **Sprint** на фиксированный цикл; используют Sprint Backlog, Burndown и Velocity. **Kanban Board:** задачи движутся непрерывно, применяются ограничения **WIP** (числа одновременно выполняемых задач).

## 4. Поиск и автоматизация

**JQL (Jira Query Language)** — язык фильтрации задач. **Filter** сохраняет запрос, **Dashboard** отображает отчёты и виджеты.

```jql
assignee = currentUser() AND statusCategory != Done
```

```jql
project = DATA AND issuetype = Bug AND statusCategory != Done
```

```jql
sprint IN openSprints() ORDER BY priority DESC
```

**Automation:** `Trigger → Condition → Action` — событие, проверка условия, действие. Например: при создании критического Bug назначить ответственного и отправить уведомление.

## 5. Как оформлять задачу

- **Название:** конкретный результат, а не «Доработать систему».
- **Контекст:** почему нужна работа и какую проблему решает.
- **Требование:** что должно измениться; для Story — ценность пользователя.
- **Acceptance Criteria:** проверяемые условия успеха, включая важные ошибки и ограничения.
- **Дополнительно:** приоритет, исполнитель, оценка, связи, макеты или документы.

**Не путать:** Epic — крупная возможность; Story — пользовательская ценность; Task — работа по реализации; Subtask — часть задачи; Bug — дефект. Jira фиксирует процесс, но сама не определяет, как команде работать.

# Урок 05. Keys, Prefixes, Listing: логическая организация объектов

> [!abstract] Цель урока
> Понять, как S3 организует объекты в плоском пространстве ключей, формирует логические «папки» и перечисляет содержимое бакета. Освоить `ListObjectsV2`, фильтрацию по префиксу и постраничное чтение результатов.

**Предварительные знания:** уроки 1–4; bucket, object, key; операции `PutObject` и `GetObject`.  
**Практическая среда:** локальный RustFS, AWS CLI, терминал `fish`.  
**Критерий завершения:** создано несколько объектов с разными ключами; получены списки по `Prefix` и `Delimiter`; выполнен переход на следующую страницу результатов.

---

## 1. Пространство ключей: плоская модель

В обычном S3-бакете (**general purpose bucket** в AWS) объект определяется ключом, а не положением в дереве каталогов. Все ключи существуют в одном логическом пространстве имён бакета.

```text
lesson05/root.txt
lesson05/docs/a.txt
lesson05/docs/b.txt
lesson05/photos/a.txt
```

Здесь **четыре объекта**, а не файлы внутри физических папок `lesson05`, `docs` и `photos`.

- **Key** — полное имя объекта внутри бакета, например `lesson05/docs/a.txt`.
- Символ `/` — часть ключа; S3 не обязан создавать каталог при его появлении.
- Объекты `docs` и `docs/a.txt` могут существовать одновременно: один ключ не является родительским каталогом другого.

**Архитектурный смысл:** логическую структуру данных задаёт приложение через соглашение об именовании ключей. Физическое распределение данных остаётся задачей хранилища.

---

## 2. Prefix: выборка по началу ключа

**Prefix (префикс)** — строка, с которой должны начинаться ключи объектов, попадающих в результат перечисления.

Для приведённых ключей:

- `Prefix=lesson05/` — все четыре объекта.
- `Prefix=lesson05/docs/` — только `a.txt` и `b.txt` в этой логической группе.
- `Prefix=lesson05/doc` — те же два объекта, поскольку сопоставляется строка, а не путь каталога.

Префикс **не является самостоятельной сущностью S3**: его не нужно создавать перед записью объекта. Запись `PutObject` с ключом `lesson05/new/file.txt` допустима без предварительного создания `lesson05/new/`.

> [!important] Prefix не управляет доступом
> Совпадение начала ключа не означает права на чтение или запись. Авторизация определяется политиками доступа, а не наличием «папки».

---

## 3. Delimiter: один уровень логической иерархии

**Delimiter (разделитель)** — символ или строка, по которой `ListObjectsV2` группирует ключи после указанного префикса. Чаще используется `/`.

При запросе `Prefix=lesson05/` и `Delimiter=/` результат содержит:

- `Contents`: объект `lesson05/root.txt`;
- `CommonPrefixes`: группы `lesson05/docs/` и `lesson05/photos/`.

**`Contents`** — сведения о конкретных объектах. **`CommonPrefixes`** — общие начала ключей, сгруппированных по разделителю. Это **не объекты и не каталоги**, хотя интерфейс может отображать их как папки.

Чтобы открыть логическую группу `docs/`, клиент повторяет операцию с `Prefix=lesson05/docs/`. Так файловый интерфейс строит навигацию по уровням, не требуя настоящего дерева каталогов.

Отдельная деталь: некоторые веб-консоли при создании «папки» записывают нулевой объект с ключом, заканчивающимся на `/`. Это обычный объект-маркер, а не обязательная часть модели S3.

---

## 4. ListObjectsV2: контракт перечисления

**`ListObjectsV2`** — операция получения перечня ключей и части сведений об объектах **в одном бакете**. Содержимое объектов не скачивается.

Основные параметры и поля ответа:

- **`Bucket`** — бакет, внутри которого выполняется перечисление.
- **`Prefix`** — ограничение ключей по начальной строке.
- **`Delimiter`** — группировка ключей в `CommonPrefixes`.
- **`MaxKeys`** — максимальное количество элементов в одном ответе; для AWS S3 предел — **1000**. Группа `CommonPrefixes` считается одним элементом.
- **`Contents` / `CommonPrefixes`** — объекты и логические группы.
- **`IsTruncated` / `NextContinuationToken`** — признак неполного результата и токен продолжения.

`ListObjectsV2` не выполняет SQL-запросы, полнотекстовый поиск или фильтрацию по произвольным пользовательским метаданным. Для таких функций приложение использует собственный каталог или индекс.

---

## 5. Pagination: получение полного списка

**Pagination** — последовательная загрузка ограниченных по размеру страниц результатов.

Алгоритм клиента:

1. Выполнить `ListObjectsV2` с нужными `Bucket`, `Prefix` и `MaxKeys`.
2. Обработать `Contents` и `CommonPrefixes` из ответа.
3. Если `IsTruncated=true`, передать значение `NextContinuationToken` в параметре `ContinuationToken` следующего запроса.
4. Повторять до `IsTruncated=false`.

**ContinuationToken — непрозрачный служебный идентификатор**, а не имя ключа и не числовой номер страницы. Приложение не должно пытаться вычислять его самостоятельно.

AWS CLI по умолчанию обрабатывает пагинацию автоматически. Флаг `--no-paginate` позволяет увидеть отдельный запрос и вручную управлять продолжением.

**Архитектурное следствие:** нельзя считать первый ответ `ListObjectsV2` полным списком объектов бакета. Для больших наборов данных клиент обязан учитывать пагинацию.

## 6. Практика: ключи, группировка и страницы

Используй бакет `s3-course-lesson1` и настроенные в предыдущих уроках AWS CLI credentials. RustFS доступен по `http://127.0.0.1:9000`.

**1. Создай четыре объекта с общим префиксом:**

```fish
printf 'lesson 05\n' > lesson05.txt
for key in lesson05/root.txt lesson05/docs/a.txt lesson05/docs/b.txt lesson05/photos/a.txt
    aws --endpoint-url http://127.0.0.1:9000 s3api put-object \
      --bucket s3-course-lesson1 --key $key --body lesson05.txt > /dev/null
end
```

**2. Посмотри один логический уровень:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api list-objects-v2 \
  --bucket s3-course-lesson1 --prefix lesson05/ --delimiter / \
  --no-paginate \
  --query '{Objects:Contents[].Key,Groups:CommonPrefixes[].Prefix}'
```

Ожидаются один ключ в `Objects` и два префикса в `Groups`.

**3. Изучи ограничение размера страницы:**

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api list-objects-v2 \
  --bucket s3-course-lesson1 --prefix lesson05/ \
  --max-keys 2 --no-paginate
```

Первая страница содержит не более двух ключей; `IsTruncated=true` означает наличие продолжения. Скопируй `NextContinuationToken` из ответа и передай его в следующем запросе:

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api list-objects-v2 \
  --bucket s3-course-lesson1 --prefix lesson05/ \
  --max-keys 2 --no-paginate \
  --continuation-token 'ТОКЕН_ИЗ_ПРЕДЫДУЩЕГО_ОТВЕТА'
```

**Критерий успеха:** обе страницы вместе дают четыре ключа без пропусков при неизменном наборе объектов.

## 7. Самостоятельные задания

1. Получи только объекты из `lesson05/docs/`. Объясни, почему префикс задаётся без создания папки.
2. Выполни перечисление с `Prefix=lesson05/` без `Delimiter`, затем с `Delimiter=/`. Сравни `Contents` и `CommonPrefixes`.
3. Объясни, почему backend с миллионами пользовательских файлов не должен выполнять полный листинг бакета для поиска файла по его отображаемому названию. Где следует хранить связь между идентификатором файла приложения и `bucket + key`?

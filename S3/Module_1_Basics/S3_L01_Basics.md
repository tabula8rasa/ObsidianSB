# Урок 01. Что такое S3 и как запустить RustFS

**Цель:** понять модель объектного хранения и создать первый объект в локальном RustFS.

## Основные понятия

- **Объектное хранилище** предоставляет доступ к данным через сетевой API, а не через локальный путь на диске сервера. Backend-инстансы обращаются к общему сервису хранения; код приложения и данные масштабируются независимо.
- **AWS S3** — объектное хранилище Amazon. **S3 API** — интерфейс операций с бакетами и объектами. **RustFS** — самостоятельное S3-совместимое хранилище. Совместимость API не означает одинаковую внутреннюю архитектуру.
- **Bucket** — именованный логический контейнер с настройками. **Object** — последовательность байтов и метаданные. **Key** — строковое имя объекта внутри бакета. Текущий объект определяется парой `(bucket, key)`; отдельная версия — также `versionId`.
- **Файловое хранение** адресуется путём, **блочное** — блоками устройства, **объектное** — через API. S3 не предоставляет обычные POSIX-операции изменения байтов по смещению.
- `docs/report.pdf` — один ключ, а не физическая вложенная папка. Символ `/` используется для группировки ключей в интерфейсах.

## Архитектура

```text
Клиент → Backend → S3 API (RustFS:9000) → данные/метаданные
                  └ Console (:9001) — отдельный веб-клиент
```

Загрузка: клиент выбирает бакет и ключ → отправляет байты → RustFS проверяет доступ и записывает объект → возвращает результат. Имя локального файла не обязано совпадать с ключом. Физическое размещение скрыто за API. **Один Docker-том не обеспечивает отказоустойчивость диска.**

## Минимальная лаборатория

Рабочий каталог и локальные учётные данные (терминал `fish`):

```bash
mkdir -p ~/s3-course/lesson-01
cd ~/s3-course/lesson-01
printf 'RUSTFS_ACCESS_KEY=lab%s\nRUSTFS_SECRET_KEY=%s\n' \
  (openssl rand -hex 8) (openssl rand -hex 24) > .env
chmod 600 .env
```

Создай `compose.yaml`:

```yaml
services:
  rustfs:
    image: rustfs/rustfs:latest
    environment:
      RUSTFS_ACCESS_KEY: ${RUSTFS_ACCESS_KEY:?set in .env}
      RUSTFS_SECRET_KEY: ${RUSTFS_SECRET_KEY:?set in .env}
      RUSTFS_VOLUMES: /data
      RUSTFS_ADDRESS: ":9000"
      RUSTFS_CONSOLE_ADDRESS: ":9001"
      RUSTFS_CONSOLE_ENABLE: "true"
    ports:
      - "127.0.0.1:9000:9000"
      - "127.0.0.1:9001:9001"
    volumes:
      - rustfs-data:/data
volumes:
  rustfs-data:
```

```bash
docker compose up -d
curl -i http://127.0.0.1:9000/health
printf 'Hello, object storage!\n' > hello.txt
```

В Console `http://127.0.0.1:9001` войди с реквизитами `.env`, создай бакет `s3-course-lesson1`, загрузи `hello.txt`, скачай объект и сравни байты через `cmp` или `sha256sum`.

## Самостоятельно

1. Загрузи один файл под двумя ключами: `hello.txt` и `notes/hello.txt`. Объясни, почему это два объекта.
2. Создай бакет `s3-course-backup`; скопируй туда содержимое и проверь, что удаление объекта в первом бакете не удаляет его во втором.
3. Выполни `docker compose down`, затем `docker compose up -d`; проверь сохранность данных. Объясни роль named volume.
4. Нарисуй схему для трёх backend-инстансов, использующих один RustFS.

**Важно:** `docker compose down` сохраняет том; `docker compose down -v` удаляет его. `.env` не публикуй в Git.

# Урок 03. Buckets: создание, проверка и удаление

**Цель:** управлять бакетами через S3 API и понимать границы их изоляции.

## Модель и ограничения

- **Namespace** — область уникальности имён. В AWS S3 имя обычного бакета в общем режиме должно быть уникальным в пределах AWS partition; локальный RustFS использует собственное пространство имён. Один `s3://bucket/key` без конфигурации endpoint не указывает однозначно сервер.
- Бакет задаёт **пространство ключей** и поддерживаемые настройки ресурса. Отдельный бакет сам по себе **не создаёт** отдельный диск, копию, пользователя или политику доступа.
- Для обычных бакетов AWS S3: имя длиной **3–63 символа**, строчные латинские буквы, цифры, дефис, точка; первая и последняя позиции — буква или цифра. Запрещены две точки подряд, формат IP-адреса и зарезервированные имена/аффиксы.
- **Изоляция доступа** требует политик. Архитектура `user-files/users/{id}/{file_id}` с одним бакетом и отдельный бакет на пользователя — разные варианты администрирования, а не разные уровни физической защиты.

## Операции над бакетом

| API | HTTP/путь | Назначение |
|---|---|---|
| `CreateBucket` | `PUT /bucket` | Создать бакет |
| `ListBuckets` | `GET /` | Перечислить бакеты |
| `HeadBucket` | `HEAD /bucket` | Проверить доступ к бакету |
| `DeleteBucket` | `DELETE /bucket` | Удалить **пустой** бакет |

**`HeadBucket`** возвращает статус без тела; `200` подтверждает разрешённый доступ. Неуспех (`403`, `404` и др.) не позволяет по одному коду уверенно различить отсутствие бакета и ограничения доступа. **`BucketNotEmpty`** означает, что перед удалением бакета нужно удалить объекты; при versioning — также версии и delete markers. `DeleteObject` не равен `DeleteBucket`.

В лаборатории используется `us-east-1` без `LocationConstraint`. У обычного AWS S3 создание в других регионах требует соответствующей конфигурации региона; это не часть локального упражнения.

## Практика

Используй сохранённую в уроке 02 команду `s3` (функция `fish`). Не удаляй бакеты предыдущих уроков.

```fish
s3 s3api create-bucket --bucket s3-course-lesson03
s3 s3api list-buckets --query 'Buckets[].Name'
s3 s3api head-bucket --bucket s3-course-lesson03
```

Проверь поведение удаления **отдельного** временного бакета:

```fish
s3 s3api create-bucket --bucket s3-course-lesson03-disposable
printf 'test\n' > temporary.txt
s3 s3api put-object --bucket s3-course-lesson03-disposable \
  --key marker.txt --body temporary.txt
s3 s3api delete-bucket --bucket s3-course-lesson03-disposable
# Зафиксируй BucketNotEmpty. Затем:
s3 s3api delete-object --bucket s3-course-lesson03-disposable --key marker.txt
s3 s3api delete-bucket --bucket s3-course-lesson03-disposable
```

## Самостоятельно

1. Создай и удали **пустой** бакет `s3-course-lesson03-task`, проверяя состояние через `ListBuckets` и `HeadBucket`.
2. Для `HeadBucket` отсутствующего бакета зафиксируй статус и объясни, почему статус не заменяет диагностику доступа.
3. Классифицируй имена `backup-2026`, `Backup-2026`, `user_files`, `my.bucket`, `192.168.0.1` по правилам AWS S3.
4. Сравни один бакет с префиксами 10 000 пользователей и 10 000 отдельных бакетов по управлению политиками и сопровождению.

**Результат:** бакет — логическая граница имён и настроек, не граница физического хранения.

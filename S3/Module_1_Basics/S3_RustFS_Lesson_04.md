# Урок 04. Объекты: PUT, GET, HEAD, DELETE

**Цель:** освоить жизненный цикл объекта и различать операции над байтами и метаданными.

## Контракт S3 API

| Операция | HTTP | Результат |
|---|---|---|
| `PutObject` | PUT | Записывает содержимое и метаданные под ключом |
| `GetObject` | GET | Возвращает байты и заголовки |
| `HeadObject` | HEAD | Возвращает сведения **без тела** |
| `DeleteObject` | DELETE | Удаляет текущий объект или создаёт delete marker при versioning |

Объект содержит **body** (произвольные байты) и **metadata**. `Content-Length` — размер тела, `Content-Type` — заявленный MIME-тип. S3 не обязан разбирать ф бакета. Текущийормат данных. Ключ выбирает клиент, а не имя исходного файла.

## Архитектура и семантика

```text
Клиент → S3 API → аутентификация/авторизация
                 → поиск bucket + key → данные/метаданные → ответ
```

- **PUT** по существующему ключу без versioning заменяет текущее содержимое; с включённым versioning создаёт новую версию. Это запись целого объекта, а не редактирование произвольных байтов по смещению.
- **GET** считывает данные; **HEAD** подходит для проверки размера, типа и состояния без передачи файла.
- **DELETE** без versioning удаляет объект; с включённым versioning обычный DELETE создаёт **delete marker** и скрывает прежнюю текущую версию. Удаление с `versionId` адресует конкретную версию.
- Успех API не раскрывает, как RustFS разместил байты на дисках и когда освободил физическое пространство. При конкурентных PUT приложение должно контролировать конфликты.

## Практика

Используй бакет `s3-course-lesson1` и функцию `s3` из урока 02:

```fish
printf 'Object storage lesson 04\n' > lesson04.txt
s3 s3api put-object --bucket s3-course-lesson1 \
  --key docs/lesson04.txt --body lesson04.txt --content-type text/plain
s3 s3api head-object --bucket s3-course-lesson1 --key docs/lesson04.txt
s3 s3api get-object --bucket s3-course-lesson1 \
  --key docs/lesson04.txt downloaded04.txt
cmp lesson04.txt downloaded04.txt
s3 s3api delete-object --bucket s3-course-lesson1 --key docs/lesson04.txt
```

**Проверка:** байты совпадают; после DELETE объект недоступен обычным GET по ключу.

## Самостоятельно

1. Загрузи другое содержимое под тем же ключом, сравни `ContentLength` до и после перезаписи.
2. Проверь HEAD до загрузки, после загрузки и после удаления. Зафиксируй результаты.
3. Спроектируй обработку двух одновременных PUT по одному ключу: как избежать незаметной потери изменений?
4. Объясни, почему удаление текущего ключа не гарантирует стирания всех версий или физического освобождения диска.

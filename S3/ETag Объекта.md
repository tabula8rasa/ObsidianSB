ETag (Entity Tag) — идентификатор состояния содержимого объекта в S3, который сервер возвращает при операциях с объектом.

Основное назначение ETag — определять, изменилось ли содержимое объекта, без его скачивания.

## 1. Для чего используется ETag

1. Проверка изменений. Клиент сохраняет ETag объекта и позднее сравнивает его с текущим ETag на сервере.
2. HTTP-кэширование. Клиент отправляет `GET` с заголовком `If-None-Match`. Если ETag совпадает, сервер отвечает `304 Not Modified`, не передавая содержимое повторно.
3. Защита от конкурентной записи. При `PUT` клиент передаёт `If-Match` с известным ETag. Если другой клиент изменил объект, S3 отклоняет запись с `412 Precondition Failed`.
4. Проверка целостности. В определённых случаях ETag равен MD5-хешу содержимого. Тогда его можно сравнить с локально вычисленным MD5. Но ETag не является универсальной контрольной суммой файла.

## 3. Почему ETag не всегда равен MD5

В AWS S3:

- Обычная загрузка `PutObject` без шифрования или с SSE-S3: ETag равен MD5 содержимого.
    
- Multipart Upload: ETag не равен MD5 всего объекта.
    
- SSE-KMS и SSE-C: ETag не является MD5 содержимого.
    

Для независимой проверки целостности необходимо использовать специальные контрольные суммы S3: SHA-256, CRC32C и другие.

Архитектурный вывод: ETag полезен для кэширования и контроля конкурентных изменений. Он не заменяет `VersionId` для идентификации конкретной версии объекта и не должен рассматриваться как универсальный криптографический хеш содержимого.

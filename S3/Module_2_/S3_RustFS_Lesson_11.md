# Урок 11. Versioning: перезапись, удаление и восстановление

> [!abstract] Цель урока
> Понять, как версионирование сохраняет историю одного ключа, и восстановить объект после обычного удаления.

**Предварительные знания:** бакеты, PUT/GET/DELETE, копирование, AWS CLI.  
**Практическая среда:** работающий RustFS, Console и настроенные реквизиты AWS CLI.  
**Время чтения:** до 5 минут; практика отдельно.  
**Критерий завершения:** две версии прочитаны отдельно, найден delete marker, обычное чтение восстановлено.

---

## 1. История вместо затирания

**Versioning** — хранение нескольких версий объекта под одним ключом. Если приложение ошибочно заменило `report.txt`, предыдущие байты остаются доступны. Это история изменений конкретного ключа.

При включённом версионировании новая загрузка с тем же ключом создаёт новую текущую версию. Предыдущая становится **noncurrent**, то есть нетекущей. Обычный GET выбирает текущую запись; для точного чтения указывают `bucket + key + versionId`.

**VersionId** — непрозрачный идентификатор, назначаемый сервером. Не пытайся вычислить его из ETag, имени файла или времени. Он не является порядковым номером, который нужно увеличивать клиенту.

## 2. Настройка относится к бакету

В AWS S3 бакет первоначально не версионируется. После включения можно установить состояние `Suspended`, но вернуть бакет в первоначальное неверсионируемое состояние нельзя. Приостановка не стирает накопленную историю и не равнозначна её очистке.

Объекты, существовавшие до включения, сохраняют версию `null`; история задним числом не возникает. Поэтому для опыта создадим пустой отдельный бакет и включим настройку до первой загрузки.

В AWS каждая версия учитывается как целый объект, а не разница между редакциями. Из этого следует необходимость заранее определить срок хранения истории. Физический способ размещения байтов RustFS через S3 API не устанавливается.

## 3. Что означает удаление

В бакете с состоянием `Enabled` обычный DELETE без `versionId` добавляет **delete marker** — специальную запись, обозначающую удалённый ключ. Предыдущие версии сохраняются. Если маркер текущий, обычный GET в AWS возвращает `404`, хотя чтение конкретной сохранённой версии остаётся возможным.

`ListObjectsV2` показывает текущие видимые объекты. Для истории нужен `ListObjectVersions`: версии данных находятся в `Versions`, маркеры — в `DeleteMarkers`. Поле `IsLatest` помогает определить текущую запись.

> [!warning] Два разных удаления
> DELETE с конкретным `versionId` окончательно удаляет выбранную запись. Если это версия данных, версионирование не позволит её вернуть. Если это текущий маркер, предыдущая запись снова станет текущей.

Повторный DELETE без идентификатора не снимает маркер: может появиться ещё один. Восстановление требует выбрать нужную запись явно.

## 4. Что проверяем в RustFS

Официальная документация RustFS описывает версии, маркеры удаления и чтение по идентификатору. Проверь это на установленном образе: запиши его тег или digest и фактический результат операций. Наличие кнопки в Console ещё не подтверждает весь сценарий.

При ошибке сохрани код ответа и версию сервера. Различай отсутствие полномочий и отсутствие поддержки операции; не считай любой отказ доказательством несовместимости. Названия элементов Console могут меняться.

## 5. Практика: удалить и вернуть

Создай в Console пустой бакет `s3-course-lesson11`, открой настройки и включи Versioning. Подготовь две редакции небольшого текстового файла с различимыми строками. Выполни опыт без параллельных записей других клиентов.

1. Загрузи первую редакцию как `report.txt`, затем вторую с **тем же ключом**.
2. Открой Versions: запиши оба идентификатора, скачай каждую версию и проверь содержимое.
3. Удали объект обычным способом, без выбора отдельной версии.
4. Посмотри историю через CLI:

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api list-object-versions --bucket s3-course-lesson11 --prefix report.txt
```

Выбери маркер именно ключа `report.txt` с `IsLatest: true`. Убедись, что обычное скачивание больше не работает, а старая версия доступна. Затем замени `MARKER_ID` его настоящим идентификатором:

```fish
aws --endpoint-url http://127.0.0.1:9000 s3api delete-object --bucket s3-course-lesson11 --key report.txt --version-id 'MARKER_ID'
```

Снова скачай объект обычным способом: ожидается вторая редакция. Для возвращения **первой** редакции скачай её по версии и загрузи под прежним ключом: появится новая текущая версия, история сохранится.

## 6. Самостоятельные задания

1. Объясни, почему снятие маркера вернуло вторую редакцию, а не первую.
2. Предложи проверку, отличающую скрытие ключа маркером от окончательного удаления версии.
3. Почему все версии на одном диске не обеспечивают защиту от его отказа?

# Урок 14. Presigned URLs: временный доступ к объекту

> [!abstract] Цель урока
> Научиться делегировать чтение и запись конкретного объекта без передачи клиенту секретного ключа и понять границы такого доступа.

**Предварительные знания:** GET/PUT, политики доступа, Signature Version 4 из урока 13.  
**Практическая среда:** работающий RustFS, настроенный профиль AWS CLI, Python с установленным `boto3`, `curl`, терминал fish.  
**Критерий завершения:** файл загружен по подписанной PUT-ссылке, скачан по GET-ссылке; ты объясняешь повторное использование и истечение срока.  
**Время чтения:** до 5 минут; практика выполняется отдельно.

---

## 1. Зачем делегировать запрос

Представь сервис фотографий. Backend проверяет пользователя и разрешает загрузить аватар. Передавать ему секрет хранилища нельзя, а пересылать все байты через backend необязательно.

**Presigned URL** — адрес с заранее вычисленной подписью запроса и ограниченным сроком действия. Backend выдаёт разрешение, клиент отправляет байты непосредственно хранилищу. При скачивании схема аналогична: backend проверяет право читать файл, затем выдаёт GET-ссылку.

Это разделение управления доступом и передачи данных: приложение принимает бизнес-решение, хранилище исполняет разрешённую операцию. Само наличие ссылки не доказывает, что пользователь является владельцем файла: такую проверку приложение делает **до её выдачи**.

## 2. Что именно разрешает ссылка

Подпись связывает запрос с методом, адресом, бакетом, ключом, параметрами и подписанными заголовками. GET-ссылка не превращается в PUT-ссылку заменой метода. Подписанный `Content-Type` потребуется передать с тем же значением.

Генерация подписи происходит локально; сервер не обязан заранее регистрировать ссылку. Поэтому успешная генерация ещё не подтверждает права подписанта, существование бакета или доступность endpoint. Всё это проверяется при обращении.

> [!warning] Ссылка — переносимое разрешение
> Ею может воспользоваться любой получатель. Не публикуй URL в логах, тикетах или аналитике. За пределами локальной лаборатории используй HTTPS. Secret Key в ссылке не содержится, но сама ссылка предоставляет доступ.

## 3. Срок и пределы доступа

В AWS S3 SigV4 допускает срок до семи дней при подходящих постоянных credentials. Временные credentials ограничивают срок дополнительно; отзыв credentials или запрещающая политика могут прекратить доступ раньше. AWS проверяет срок при начале запроса: уже начавшееся скачивание может продолжаться после истечения.

Ссылка **не одноразовая**. Пока доступ разрешён, PUT можно повторить: текущий объект по этому ключу будет заменён, а при включённом versioning появится новая версия. Поэтому приложение выбирает уникальный ключ и не позволяет клиенту произвольно указывать чужой объект.

Обычная PUT-ссылка также не гарантирует допустимость содержимого. После загрузки приложение должно проверить размер и фактический формат, прежде чем считать файл принятым. Отдельного универсального действия «отозвать только эту ссылку» в такой схеме нет: заранее выбирай короткий срок.

## 4. AWS S3 и RustFS

Официальное руководство RustFS показывает подписанные GET и PUT через boto3. Это подтверждение документированного сценария API, а не обещание идентичных AWS политик и ограничений во всех версиях. Запиши версию своей сборки и результаты эксперимента.

Endpoint должен быть доступен **получателю**. Нельзя подписать адрес контейнера, затем заменить hostname на публичный: `Host` участвует в подписи. Здесь клиент и RustFS находятся на одном компьютере, поэтому используем `127.0.0.1:9000`.

## 5. Практика: разрешение отдельно от передачи

Используй существующий учебный бакет `s3-course-lesson1`. Сохрани следующий код как `presign.py`. Он читает credentials из настроенной стандартной цепочки AWS; если используешь именованный профиль, задай `AWS_PROFILE`. Не вставляй секреты в код.

```python
import boto3
from botocore.config import Config

s3 = boto3.client(
    "s3", endpoint_url="http://127.0.0.1:9000",
    region_name="us-east-1",
    config=Config(signature_version="s3v4",
                  s3={"addressing_style": "path"}),
)
for operation in ("put_object", "get_object"):
    print(s3.generate_presigned_url(
        operation,
        Params={"Bucket": "s3-course-lesson1", "Key": "lesson14/upload.txt"},
        ExpiresIn=300,
    ))
```

Запусти `python presign.py`. Первую строку используй как PUT_URL, вторую — как GET_URL; вставляй адреса целиком внутри кавычек:

```bash
printf 'Temporary access\n' > upload.txt
set PUT_URL 'вставь первую ссылку'
set GET_URL 'вставь вторую ссылку'
curl --fail-with-body -T upload.txt "$PUT_URL"
curl --fail-with-body "$GET_URL" -o downloaded.txt
cmp upload.txt downloaded.txt
```

`-T` выбирает PUT. Ожидай успешные HTTP-ответы и отсутствие различий у `cmp`. При ошибке проверь XML-код: неверный метод/адрес связан с подписью, недостаточные права — с авторизацией. Не делай бакет публичным ради исправления ошибки.

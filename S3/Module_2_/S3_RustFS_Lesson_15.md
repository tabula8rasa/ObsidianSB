# Урок 15. Lifecycle и Object Lock

> [!abstract] Цель урока
> Разделить автоматическую очистку и обязательное удержание данных, настроить правило жизненного цикла и проверить защиту конкретной версии.

**Предварительные знания:** AWS CLI, политики доступа, версионирование, delete markers.  
**Практическая среда:** локальный RustFS, настроенный профиль AWS CLI `rustfs`, терминал `fish`.  
**Критерий завершения:** правило прочитано обратно через API, попытка удаления защищённой версии проверена, ограничения установленной версии записаны.  
**Время чтения:** до 5 минут; наблюдение фоновой очистки выполняется отдельно.

---

## 1. Два разных вопроса о времени

В файловом сервисе временные выгрузки нужно удалять, а подписанные документы — сохранять. **Lifecycle** отвечает: «Когда данные следует перевести или удалить?» **Object Lock**: «До какого момента удаление версии запрещено?»

Первый механизм автоматизирует обслуживание, второй ограничивает допустимые изменения. Versioning сохраняет историю, но само по себе не запрещает удалить старую версию. Ни один из этих механизмов не заменяет резервную копию на независимом носителе.

## 2. Как работает Lifecycle

Правило принадлежит бакету и содержит идентификатор, состояние, фильтр объектов и действия. Фильтр может выбирать префикс, теги или размер. В AWS основные действия — **Transition**, переход в другой класс хранения, и **Expiration**, истечение срока хранения.

Например, архивные данные можно переводить из S3 Standard в S3 Glacier Flexible Retrieval. Выбор зависит от требований к чтению и стоимости хранения, извлечения и переходов. Это возможности облачного сервиса AWS; одинаковый S3 API не создаёт такие классы на локальном диске RustFS.

При включённом versioning истечение текущей версии данных создаёт delete marker. Байты прежней версии остаются. Для окончательной очистки нетекущих версий существует отдельное действие `NoncurrentVersionExpiration`.

> [!note] Срок — условие запуска, а не точный таймер
> В AWS удаление выполняется асинхронно. Принятие правила подтверждает сохранение конфигурации, но ещё не подтверждает работу фонового исполнителя.

## 3. Что защищает Object Lock

**WORM** означает «однократная запись, многократное чтение». Защита относится к версии, поэтому важен полный адрес: бакет, ключ и `VersionId`.

Для фиксированного retention задают дату `RetainUntilDate`. Режим **GOVERNANCE** допускает обход при специальном разрешении и явно переданном признаке обхода. **COMPLIANCE** в AWS запрещает удалить защищённую версию или сократить срок даже root-пользователю. **Legal hold** действует без даты окончания, пока уполномоченный пользователь его не снимет.

Новая запись с тем же ключом создаёт другую версию. Удаление без `VersionId` может создать маркер, скрывающий объект из обычного чтения; это не уничтожение защищённых байтов.

В AWS Lifecycle не удаляет заблокированную версию, хотя может создавать маркеры и выполнять переходы между классами хранения. После окончания retention версия лишь становится доступной для удаления: немедленная очистка не гарантируется.

## 4. Практика: настройка и проверка

Матрица RustFS подтверждает отдельные тесты Lifecycle и Object Lock, а не полную совместимость. Запиши версию образа. Используй отдельный пустой лабораторный бакет; проверяй ответы своей сборки.

Создай бакет с возможностью блокировки:

```fish
aws --profile rustfs --endpoint-url http://127.0.0.1:9000 s3api create-bucket --bucket lesson15-lab --object-lock-enabled-for-bucket
```

Через `GetBucketVersioning` и `GetObjectLockConfiguration` проверь включение возможностей. При ошибке сначала отличи отсутствие прав от неподдерживаемой операции.

Сохрани в `lifecycle.json` правило:

```json
{"Rules":[{"ID":"expire-tmp","Status":"Enabled","Filter":{"Prefix":"tmp/"},"Expiration":{"Days":1}}]}
```

Примени его:

```fish
aws --profile rustfs --endpoint-url http://127.0.0.1:9000 s3api put-bucket-lifecycle-configuration --bucket lesson15-lab --lifecycle-configuration file://lifecycle.json
```

Прочитай конфигурацию через `GetBucketLifecycleConfiguration`. Затем загрузи небольшой файл с ключом `tmp/check.txt`, сохрани возвращённый `VersionId`. Через `PutObjectRetention` установи этой версии `GOVERNANCE` и дату UTC на десять минут вперёд; прочитай параметры через `GetObjectRetention`.

Вызови `DeleteObject` **с сохранённым VersionId**, без обхода governance. Ожидается отказ. После срока повтори запрос: при необходимых правах удаление должно пройти. Запиши фактические ответы. Ожидание выполняется отдельно; минутная проверка retention не заменяет суточный эксперимент Lifecycle.

> [!warning] Граница опыта
> Отказ удаления проверяет поведение API. Он не доказывает защиту от администратора физического диска. Не изменяй Docker-том вручную.

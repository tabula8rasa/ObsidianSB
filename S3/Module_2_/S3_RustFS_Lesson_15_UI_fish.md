# Урок 15. Lifecycle и Object Lock

> [!abstract] Цель урока
> Настроить срок автоматического удаления объектов и защиту версий от удаления в **RustFS Console**. Проверить результат в интерфейсе и, где необходим точный `VersionId`, в терминале **fish**.

**Среда:** локальный RustFS, доступ администратора к RustFS Console, AWS CLI с профилем `rustfs`.  
**Итог:** создан бакет с Object Lock, применено правило Lifecycle, проверено удержание версии и различие между удалением ключа и версии.  
**Время чтения:** до 5 минут. Ожидание истечения сроков в это время не входит.

---

## 1. Lifecycle и Object Lock решают разные задачи

- **Lifecycle** — правила управления жизненным циклом объектов бакета. Например, удалить объекты с префиксом `tmp/` спустя день.
- **Object Lock** — запрет удаления **определённой версии** объекта до заданного времени (retention) или до снятия Legal Hold.
- **Versioning** сохраняет отдельные версии одного ключа, но не запрещает удаление конкретной версии само по себе.

Если у текущей версии истекает срок Lifecycle в бакете с versioning, создаётся **delete marker**. Прежние версии при этом остаются. Для удаления старых версий требуется отдельная настройка `NoncurrentVersionExpiration`.

В AWS при Object Lock режим **GOVERNANCE** допускает обход при специальных правах и явном флаге, а **COMPLIANCE** запрещает сокращать срок защиты. Для локального RustFS проверяй фактические ответы своей версии сервера: совместимость S3 API не означает подтверждения всех гарантий AWS.

## 2. Создай учебный бакет в RustFS Console

1. Открой RustFS Console (используй адрес и порт интерфейса из своего развёртывания, **не** S3 API endpoint `:9000`). Авторизуйся администратором.
2. Перейди в **Buckets / Bucket Settings** и нажми **Create Bucket**.
3. Название: `lesson15-lab` (если оно уже занято, удали прежний *учебный* бакет или выбери другое имя и далее используй его).
4. Включи **Versioning** и **Object Lock**.
5. **Retention** на уровне бакета **не включай**: это срок по умолчанию для всех новых версий. В этом уроке будем задавать защиту только одному файлу.
6. Нажми **Create**. Открой бакет и проверь в его настройках статусы **Versioning: Enabled** и **Object Lock: Enabled**.

> [!warning] Важно
> Object Lock нужно включать при создании учебного бакета. Не используй существующий бакет с рабочими данными. Режим COMPLIANCE не нужен для этого опыта.

## 3. Создай правило Lifecycle в интерфейсе

1. Открой **Buckets → lesson15-lab → Lifecycle** (вкладка настроек бакета).
2. Нажми **Add Lifecycle Rule**.
3. Выбери вкладку **Expiration**.
4. Установи **Days: 1**, **Prefix: `tmp/`**; фильтрацию по тегам не добавляй.
5. Если форма предлагает отдельный режим для **noncurrent versions**, не смешивай его с удалением текущих объектов: нужно сначала создать правило для текущих версий. Интерфейс может создавать несколько технических правил в зависимости от версии бакета.
6. Сохрани правило. Убедись, что оно появилось в списке Lifecycle с включённым статусом.

**Результат:** конфигурация сохранена. Это **не** доказывает, что через 24 часа физически удалятся все байты: при versioning истечение текущей версии создаёт delete marker, а фоновый исполнитель срабатывает отдельно.

## 4. Загрузи объект и включи защиту

1. В Console открой файловый браузер (**Object Browser / Browser**) и перейди в `lesson15-lab`.
2. Создай каталог `tmp`, если интерфейс предлагает такую операцию, либо загрузи небольшой текстовый файл с ключом `tmp/check.txt`. В S3 каталог — это часть ключа, а не обязательная физическая директория.
3. Открой сведения о `tmp/check.txt` (**Object Info / Details**).
4. Найди раздел **Retention** и укажи **GOVERNANCE** и дату/время окончания **на 1 день вперёд**. Сохрани.
5. Вернись в сведения об объекте и проверь отображаемые режим и дату удержания. **Legal Hold** оставь выключенным.
6. В списке версий (**Object Versions / Versions**) найди созданную версию и сохрани её `VersionId`, если интерфейс его показывает.

> [!note] Почему один день, а не десять минут
> В веб-форме бакета срок retention по умолчанию задаётся целыми днями или годами. Форма удержания отдельного объекта использует дату окончания. Если твоя сборка Console не позволяет задать требуемое время либо не показывает `VersionId`, используй точечную проверку через CLI в следующем разделе.

## 5. Проверь удаление без путаницы с версиями

**Через UI:** попробуй удалить объект `tmp/check.txt` из обычного списка объектов. Затем открой **Versions / Object Versions**.

- Удаление **ключа без `VersionId`** в версионируемом бакете создаёт delete marker. Поэтому исчезновение файла из обычного списка **не доказывает удаления защищённой версии**.
- Для строгой проверки Object Lock необходимо удалить **конкретную версию с `VersionId`**, не используя обход governance.
- Не нажимай «удалить все версии» и не обходи защиту административными инструментами.

**Точная проверка в fish** (работает независимо от того, умеет ли твоя Console передавать `VersionId` при удалении):

```fish
set -gx EP http://127.0.0.1:9000
set -gx B lesson15-lab
aws --profile rustfs --endpoint-url $EP s3api list-object-versions --bucket $B --prefix tmp/check.txt
```

Скопируй нужный `VersionId` из массива `Versions`, затем:

```fish
set -gx V 'ВСТАВЬ_VERSION_ID'
aws --profile rustfs --endpoint-url $EP s3api get-object-retention --bucket $B --key tmp/check.txt --version-id $V
aws --profile rustfs --endpoint-url $EP s3api delete-object --bucket $B --key tmp/check.txt --version-id $V
```

**Ожидаемый результат:** пока действует GOVERNANCE и нет явного разрешённого обхода, удаление защищённой версии отклоняется. Запиши HTTP/S3 ошибку, если реализация ведёт себя иначе. После окончания удержания удаление версии можно повторить.

**Дополнительная проверка правила Lifecycle:**

```fish
aws --profile rustfs --endpoint-url $EP s3api get-bucket-lifecycle-configuration --bucket $B
```

Команда не изменяет состояние. Сравни полученный JSON с настройкой в Console: названия и количество фактических правил могут отличаться от числа шагов в форме.

## 6. Что проверить после истечения суток

1. Обнови объектный браузер и список версий; посмотри, появился ли delete marker.
2. Проверь, осталась ли защищённая версия. Не путай видимость текущего ключа с существованием его старых версий.
3. Если delete marker не создан, запиши версию RustFS, правило и результат `list-object-versions`: наличие сохранённого правила не доказывает выполнение фоновой очистки.
4. Если нужен полный сборщик старых версий, изучи отдельное правило для **noncurrent versions**. Не добавляй его в этот опыт: оно осложнит наблюдение.

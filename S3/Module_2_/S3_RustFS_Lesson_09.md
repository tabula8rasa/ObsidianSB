# Урок 09. Multipart Upload: один объект, несколько запросов

**Цель**: Понять жизненный цикл загрузки частями, завершить одну загрузку и отменить другую, различая передачу данных и внутреннюю избыточность хранилища.

---

## 1. Зачем разбивать передачу

При обычном PUT сбой ближе к концу передачи большого файла заставляет повторять весь запрос. **Multipart Upload** позволяет передавать непрерывные участки одного объекта независимо. Неудачную часть можно отправить заново, сохранив остальные. Параллельная отправка помогает использовать сеть, но увеличивает число запросов и потребление ресурсов клиента.

Архитектурная цена — появление состояния загрузки. Приложению нужно помнить идентификатор сессии, номера частей и результаты запросов, а также отвечать за завершение или уборку. Автоматическое восстановление после перезапуска клиента требует сохранения этого состояния самим клиентом.

## 2. Четыре операции и граница публикации

1. `CreateMultipartUpload` начинает загрузку для пары bucket/key и возвращает `UploadId`. Метаданные будущего объекта задают здесь.
2. `UploadPart` получает `UploadId`, номер части и её байты. Ответ содержит `ETag`, который следует сохранить вместе с номером.
3. `CompleteMultipartUpload` получает упорядоченный список номеров и соответствующих ETag. Сервис объединяет части по возрастанию номеров и создаёт объект.
4. `AbortMultipartUpload` отменяет незавершённую загрузку и освобождает связанные ресурсы.

До успешного завершения части не являются новым объектом, доступным обычным GET. Если выбран новый ключ, HEAD ещё не найдёт его. Для существующего ключа не следует ожидать чтения «частично обновлённого файла».

Повторная отправка того же номера в рамках одного `UploadId` заменяет соответствующую часть. Порядок отправки может отличаться от порядка сборки. Для простоты используй последовательные номера начиная с 1.

## 3. API и физическое хранение

В AWS S3 допускается до 10 000 частей, каждая от 5 MiB до 5 GiB; последняя может быть меньше 5 MiB. Размер части определяет баланс между числом запросов и стоимостью повтора.

Матрица совместимости RustFS отмечает базовые create/upload/complete/abort как проверенные. Это не обещание полной идентичности всех граничных случаев AWS. Запиши версию установленного RustFS и результат опыта; ограничения AWS нельзя автоматически объявлять ограничениями RustFS.

> [!important] Части передачи — не фрагменты отказоустойчивости
> Multipart описывает протокол загрузки. Он не задаёт размещение на дисках, репликацию или erasure coding. Завершение multipart в нашей SNSD-лаборатории не добавляет защиты от отказа диска.

## 4. Практика: собираем небольшой учебный объект

Чтобы увидеть механизм, достаточно 12 MiB. В отдельном рабочем каталоге создай файл и две части:

```bash
dd if=/dev/urandom of=source.bin bs=1M count=12 status=none
split -b 6M source.bin part-
set EP http://127.0.0.1:9000
set B s3-course-lesson1
set U (aws --endpoint-url $EP s3api create-multipart-upload --bucket $B --key lesson09/complete.bin --query UploadId --output text)
```

Отправь части и сохрани ответы:

```bash
aws --endpoint-url $EP s3api upload-part --bucket $B --key lesson09/complete.bin --upload-id $U --part-number 1 --body part-aa > response1.json
aws --endpoint-url $EP s3api upload-part --bucket $B --key lesson09/complete.bin --upload-id $U --part-number 2 --body part-ab > response2.json
```

Создай `parts.json`, подставив значения ETag из ответов:

```json
{"Parts":[{"PartNumber":1,"ETag":"\"ETAG_1\""},{"PartNumber":2,"ETag":"\"ETAG_2\""}]}
```

Переноси значение целиком: внутренние кавычки ETag в JSON экранируются. Не вычисляй ETag самостоятельно. Перед завершением проверь через `head-object`, что новый ключ отсутствует; ошибка доступа сама по себе отсутствия не доказывает.

```bash
aws --endpoint-url $EP s3api complete-multipart-upload --bucket $B --key lesson09/complete.bin --upload-id $U --multipart-upload file://parts.json
aws --endpoint-url $EP s3api get-object --bucket $B --key lesson09/complete.bin downloaded.bin
cmp source.bin downloaded.bin
```

**Критерий успеха:** завершение успешно, `cmp` не сообщает различий.

## 5. Отмена и ответственность клиента

Повтори создание и отправку только первой части с новым ключом `lesson09/aborted.bin`. Сохрани новый `UploadId` в `U`. Затем:

```bash
aws --endpoint-url $EP s3api abort-multipart-upload --bucket $B --key lesson09/aborted.bin --upload-id $U
```

Проверь через `list-multipart-uploads`, что этот идентификатор отсутствует, а завершённый объект первой загрузки доступен.

> [!warning] Незавершённая загрузка требует уборки
> В AWS загруженные части занимают оплачиваемое место до завершения или отмены. Перед отменой останови отправителей и дождись окончания текущих запросов. Lifecycle для автоматической уборки рассмотрим позднее.

## 6. Самостоятельные задания

1. Повтори опыт, отправив вторую часть раньше первой. Объясни результат сравнения файлов.
2. Предложи, какие сведения должен сохранять клиент для продолжения после перезапуска.
3. Объясни, почему отсутствие ключа в обычном листинге не доказывает отсутствие незавершённых загрузок.

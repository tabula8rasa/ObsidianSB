# Урок 10. Проверка целостности: ETag, MD5 и SHA-256

> [!abstract] Цель урока
> Научиться проверять сохранённые байты и объяснять, почему ETag нельзя автоматически считать контрольной суммой файла.

**Предварительные знания:** PUT, GET, HEAD, условные запросы и multipart upload из урока 9.  
**Практическая среда:** работающий RustFS, настроенный AWS CLI, терминал `fish`, `sha256sum` и `md5sum`.  
**Критерий завершения:** ты сравнил исходный и скачанный объект, записал ETag и объяснил границы этой проверки.  
**Время чтения:** до 5 минут; практика выполняется отдельно.

---

## 1. Что именно проверяем

**Целостность** означает, что проверяемые байты соответствуют ожидаемым. Успешный HTTP-ответ сообщает о выполнении операции, но приложению иногда нужна независимая проверка содержимого: например, перед удалением исходного архива.

**Контрольная сумма** — значение, вычисленное из последовательности байтов по определённому алгоритму. Сначала клиент считает сумму исходного файла, затем сравнивает её с суммой полученных данных. Эталон нужно получить до передачи и сохранить отдельно.

Равенство размера недостаточно: два документа одинаковой длины могут содержать разные байты. Проверка также относится к конкретному моменту: последующая перезапись ключа изменит объект.

## 2. MD5 и SHA-256

**MD5** даёт 128-битный результат, **SHA-256** — 256-битный. Одинаковые байты при одном алгоритме дают одинаковую сумму. Разные алгоритмы между собой не сравнивают.

MD5 полезен для понимания старых механизмов S3, но не подходит для защиты от намеренно подобранных коллизий. Для собственного эталона выберем SHA-256. Даже криптографический хеш сам по себе не доказывает авторство: злоумышленник, заменивший и файл, и доступный ему эталон, обойдёт такую проверку.

Учитывай представление результата: Linux-утилиты обычно печатают hex, а поля S3 checksums передают значение в Base64. Разные строки ещё не означают разные контрольные суммы.

## 3. Почему ETag не равен MD5 по определению

**ETag** — возвращаемый сервисом тег объекта, используемый, в частности, в условных запросах. Рассматривай его как непрозрачное значение, пока документация не гарантирует конкретный способ вычисления.

В обычных бакетах AWS S3 ETag объекта после одиночного PUT без шифрования или с SSE-S3 соответствует MD5 содержимого. Для multipart upload, SSE-KMS и SSE-C такого равенства нет. Поэтому изменение способа загрузки способно изменить ETag при тех же исходных байтах.

> [!warning] ETag — не паспорт файла
> Нельзя строить универсальную проверку целостности или поиск дубликатов на предположении «ETag всегда MD5». Правила AWS также нельзя автоматически переносить на установленную сборку RustFS.

## 4. Отдельные S3 checksums

AWS S3 поддерживает явные контрольные суммы, включая SHA-256 и CRC. При передаче ожидаемой суммы сервис вычисляет свою и проверяет совпадение; неверное значение приводит к отказу, например `BadDigest`.

Различай **FULL_OBJECT** — сумму всего содержимого, и **COMPOSITE** — результат, полученный из сумм частей. Для multipart SHA-256 в AWS используется составной вариант: сравнивать его напрямую с `sha256sum` целого файла нельзя.

Сохранённую сумму можно запросить через HEAD или GET с включённым checksum mode. HEAD возвращает метаданные, поэтому сам по себе не проверяет байты на диске повторным чтением. Пользовательское поле `x-amz-meta-sha256` также не заставляет сервер проверять содержимое.

RustFS документирует S3-совместимый интерфейс, однако поддержку конкретного алгоритма, типа суммы и режима запроса проверяй на своей версии. В этой практике независимый локальный хеш остаётся основным способом проверки.

## 5. Практика: замыкаем путь данных

Используй существующий лабораторный бакет `s3-course-lesson1` и настроенные реквизиты CLI. Выполни:

```fish
printf 'Integrity check\n' > integrity.txt
md5sum integrity.txt
sha256sum integrity.txt
aws --endpoint-url http://127.0.0.1:9000 s3api put-object \
    --bucket s3-course-lesson1 --key lesson10/integrity.txt --body integrity.txt
aws --endpoint-url http://127.0.0.1:9000 s3api get-object \
    --bucket s3-course-lesson1 --key lesson10/integrity.txt downloaded-integrity.txt
sha256sum integrity.txt downloaded-integrity.txt
```

Запиши ETag из ответа PUT и сравни его с MD5, убрав только внешние кавычки. Совпадение — наблюдение для этой загрузки, а не гарантия поведения всех объектов.

**Ожидаемый результат:** обе SHA-256 совпадают. Теперь допиши символ только в скачанный файл и повтори последнюю команду: суммы должны различаться. Объект в RustFS при этом не меняется.

## 6. Самостоятельные задания

1. Скачай готовый multipart-объект из урока 9 и сравни SHA-256 с исходником. Объясни результат независимо от формы ETag.
2. Сформулируй, почему сохранённая рядом с объектом строка хеша слабее независимого доверенного эталона.
3. Предложи действия приложения при несовпадении сумм. Учти возможность локального изменения исходника и конкурентной перезаписи ключа.

# Урок 12. Управление доступом: кто может выполнить запрос

> [!abstract] Цель урока
> Различать идентификацию пользователя и проверку его прав; ограничить доступ одним бакетом и подтвердить границу разрешёнными и запрещёнными запросами.

**Предварительные знания:** бакеты, ключи, операции S3 и профили AWS CLI.  
**Практическая среда:** работающий RustFS, Console, AWS CLI.  
**Время чтения:** до 5 минут.  
**Критерий завершения:** отдельный пользователь читает объекты одного бакета, но не может писать в него или читать другой бакет.

---

## 1. Два разных вопроса сервера

**Аутентификация** отвечает: «Кто отправил запрос?» **Авторизация**: «Разрешено ли этому субъекту это действие над этим ресурсом?» Корректные ключи доступа сами по себе не дают права скачать произвольный объект.

**IAM** — управление идентичностями и доступом. Пользователь представляет человека или приложение; политика описывает разрешения. Группа объединяет пользователей общими политиками. Приложению предоставляют минимальные права.

Проверка доступа выполняется сервером для каждого запроса. Скрытая кнопка удаления не заменяет запрет `DeleteObject`.

## 2. Политика описывает действие и ресурс

В JSON-политике `Effect` задаёт `Allow` или `Deny`, `Action` — разрешение, `Resource` — область действия. Например, листинг бакета и чтение объектов требуют разных ресурсов:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::lesson12-private"
    },
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::lesson12-private/*"
    }
  ]
}
```

Первый ARN обозначает бакет; окончание `/*` — его объекты. ARN идентифицирует ресурс, а не сетевой адрес.

Имя разрешения не всегда совпадает с именем API: `ListObjectsV2` проверяет `s3:ListBucket`. Разрешение на листинг не разрешает читать содержимое, а чтение по известному ключу не требует предварительного листинга.

## 3. Где закрепляются правила

**Identity policy** назначают пользователю или группе: что разрешено этой идентичности? **Bucket policy** закрепляют за бакетом: кому разрешены действия над этим ресурсом? В ресурсной политике поле `Principal` указывает субъекта.

Для обычного пользователя отсутствие подходящего разрешения означает отказ; применимый явный `Deny` имеет приоритет над `Allow`. В AWS итог зависит также от других ограничений, например политик организации. Поэтому одна разрешающая запись не гарантирует успешный запрос.

**ACL** — отдельный механизм списков предоставленных прав для бакетов и объектов. В новых обычных бакетах AWS S3 ACL по умолчанию отключены настройкой `Bucket owner enforced`; доступ задают политиками.

> [!warning] Не открывай бакет ради исправления ошибки
> `AccessDenied` требует проверки субъекта, действия, ресурса и применимых запретов. Публичная политика с `Principal: "*"` способна открыть данные посторонним.

## 4. AWS IAM и RustFS IAM

AWS IAM обслуживает множество сервисов AWS. RustFS имеет собственную систему пользователей и политик, использующую похожий язык. Проверяй поддержку возможностей отдельно.

Создание пользователей RustFS выполняют через Console или административный API RustFS. Команда `aws iam create-user` не становится подходящей только из-за настройки S3 endpoint. S3-запросы проверяем AWS CLI, управление идентичностями выполняем средствами RustFS.

Сверяй Console с установленной версией. Поддержку ACL и условий AWS проверяй отдельно.

## 5. Практика: один пользователь, один бакет

1. Администратором создай приватные бакеты `lesson12-private` и `lesson12-other`; положи в каждый `hello.txt`. Не добавляй публичных разрешений.
2. В разделе Identity Console создай пользователя `lesson12-reader` с отдельным секретом. Назначь пользователю показанную политику. Не добавляй широких встроенных политик или групп.
3. Выполни `aws configure --profile lesson12-reader`, введи его реквизиты и регион лаборатории. Проверь переменные окружения: они не должны подменять credentials.
4. Выполни два запроса:

```fish
aws --profile lesson12-reader --endpoint-url http://127.0.0.1:9000 s3api get-object --bucket lesson12-private --key hello.txt downloaded.txt
aws --profile lesson12-reader --endpoint-url http://127.0.0.1:9000 s3api get-object --bucket lesson12-other --key hello.txt forbidden.txt
```

Первый запрос должен вернуть объект, второй — `AccessDenied`. Затем тем же профилем попробуй загрузить `downloaded.txt` в разрешённый бакет: запись также должна завершиться отказом.

> [!important] Проверяй границу
> Успешное чтение доказывает наличие разрешения. Отказ соседнему бакету и отказ записи подтверждают ограничение проверенных операций. Не выполняй проверки административным профилем.

## 6. Самостоятельные задания

1. Объясни, почему разрешение на `lesson12-private/*` не заменяет разрешение листинга самого бакета.
2. Убери `s3:ListBucket`: предскажи результат чтения известного ключа и листинга, затем проверь.
3. Если запрещённая операция неожиданно проходит, проверь фактические credentials, членство в группах и bucket policy. Какой источник предоставил лишнее разрешение?

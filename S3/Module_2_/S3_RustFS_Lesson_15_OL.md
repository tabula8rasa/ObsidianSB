# S3 Object Lock (RustFS)

**Object Lock** — механизм WORM (*Write Once, Read Many*), который защищает **конкретные версии объектов** от окончательного удаления в течение заданного срока или до снятия удержания.

- Работает только в бакете с **Versioning = Enabled** и включённым Object Lock.
- Защита применяется **к версии (`VersionId`)**, а не ко всему ключу (`Key`). У разных версий одного файла могут быть разные ограничения.
- Включённая функция Object Lock **сама по себе не защищает все версии**: удержание должно быть установлено на версии явно или унаследовано из настроек бакета.

## 1. Retention — Governance

**Что защищает:** версию объекта, для которой установлен режим `GOVERNANCE` и дата `RetainUntilDate`.

- До указанной даты запрещает окончательное удаление версии и сокращение срока удержания обычными запросами.
- Привилегированный пользователь может обойти ограничение при наличии права `s3:BypassGovernanceRetention` **и** явного признака обхода (`x-amz-bypass-governance-retention: true`).
- Срок удержания можно продлевать.
- По достижении `RetainUntilDate` защита по времени прекращается; **автоматическое удаление не происходит само по себе**.

**Назначение:** защита от случайного удаления с возможностью административного исключения.

## 2. Retention — Compliance

**Что защищает:** версию объекта с режимом `COMPLIANCE` и датой `RetainUntilDate`.

- До указанной даты версия не может быть окончательно удалена даже администратором.
- Нельзя сократить срок удержания или заменить режим на менее строгий.
- Увеличить срок удержания можно.
- По окончании срока версия становится доступной для удаления, если нет других действующих ограничений.

**Назначение:** строгое неизменяемое хранение на фиксированный срок.

## 3. Legal Hold

**Что защищает:** конкретную версию объекта, для которой установлено `LegalHold = ON`.

- Запрещает окончательное удаление версии **без установленной даты окончания**.
- Снимается только отдельным разрешённым действием: `LegalHold = OFF`.
- Работает независимо от `GOVERNANCE` и `COMPLIANCE`.
- Если включены и Retention, и Legal Hold, удаление возможно только после прекращения **обоих** ограничений.
- Обход Governance **не отключает** Legal Hold.

**Назначение:** удержание данных до явного решения об освобождении версии.

## 4. Уровень бакета и уровень версии

- **Object Lock Enabled на бакете** — разрешает использовать защиту версий; сам по себе не задаёт каждому объекту срок удержания.
- **Default Retention на бакете** — автоматически назначает режим (`GOVERNANCE` / `COMPLIANCE`) и продолжительность (дни / годы) **новым версиям**, если для них не задано явное удержание.
- **Object Retention на конкретной версии** — хранит режим и дату `RetainUntilDate` именно этой версии.
- **Legal Hold** устанавливается и снимается для отдельных версий, независимо от стандартного срока Retention.

## 5. Object Lock и Versioning / Delete Markers

- `PUT Object` с тем же ключом **создаёт новую версию**. Защищённая старая версия не перезаписывается и сохраняет свои ограничения.
- Обычный `DELETE Object` **без `versionId`** может создать **Delete Marker**, даже если под ним есть защищённая версия. Данные защищённой версии не удаляются.
- `DELETE Object` **с `versionId`** обращается к конкретной версии: если она защищена, окончательное удаление блокируется.
- **Delete Marker не наследует Object Lock** от версий с данными и сам по себе не защищён Retention или Legal Hold.
- Удаление текущего Delete Marker может снова сделать предыдущую версию видимой через обычный `GET`.

## 6. Object Lock и Lifecycle

- **Current Version Expiration** может создать Delete Marker над защищённой текущей версией. Содержимое защищённой версии остаётся.
- **Non-current Version Expiration** не может окончательно удалить защищённую версию до окончания Retention и снятия Legal Hold.
- **Transition (Current / Non-current)** переносит данные между уровнями хранения **без снятия Object Lock**. Защита остаётся привязана к той же версии.
- **Delete Marker Handling** не снимает защиту с версий данных и не позволяет их удалить.
- Окончание Retention **не запускает удаление само по себе**: оно лишь снимает препятствие для явного DELETE или применимого Expiration.

# S3 Lifecycle: Expiration и Transition (RustFS)

**Lifecycle** — правила автоматической обработки объектов бакета по сроку и фильтрам. Ниже рассматривается бакет с **Versioning = Enabled**.

- **Current version** — актуальная версия ключа: обычный `GET Object` обращается именно к ней. Текущей версией может быть и Delete Marker.
- **Non-current version** — прежняя версия ключа, переставшая быть текущей после новой загрузки или создания Delete Marker.
- **Delete Marker** — специальная версия без содержимого. Когда она текущая, обычный `GET Object` возвращает `404`; версии с данными при этом могут сохраняться.

## 1. Expiration — Current Version

**Над чем действует:** над текущей версией объекта с данными.

- Срок `Days After` отсчитывается от создания текущей версии.
- При наступлении срока **создаётся Delete Marker**, который становится Current.
- Предыдущая текущая версия становится **Non-current** и сохраняет данные.
- Обычный `GET Object` перестаёт возвращать файл, но сохранённую версию можно запросить по `versionId`.
- **Не удаляет физически** версии с данными при включённом Versioning.

Если текущая версия уже Delete Marker, новое удаление поверх неё правило не выполняет.

## 2. Expiration — Non-current Version

**Над чем действует:** над прежними версиями объекта с данными.

- Срок `NoncurrentDays` отсчитывается **с момента, когда версия перестала быть Current**, а не с момента её первоначальной загрузки.
- По наступлении срока соответствующая версия **удаляется окончательно**.
- Не создаёт Delete Marker.
- Не затрагивает действующую Current версию.
- Если версия перенесена в удалённый tier, RustFS также инициирует очистку её данных в этом tier; физическая очистка выполняется асинхронно.

## 3. Delete Marker Handling

**Над чем действует:** над **текущим Delete Marker, который остался единственной версией ключа** (`Expired Object Delete Marker`).

- Удаляет такой Delete Marker без отдельного срока `Days`.
- Не удаляет версии с данными.
- Не очищает всю историю маркеров автоматически.
- Если задано только `Expiration.Days`, одиночный истёкший маркер также может очищаться по возрастному условию; отдельное правило позволяет делать это без ожидания срока.

**Особенность RustFS Console:** при выборе *Current Version + Delete Marker Handling* создаются **два правила** (`Expiration.Days` и `ExpiredObjectDeleteMarker`). При выборе *Non-current Version + Delete Marker Handling* оба действия могут быть записаны в **одно правило**.

## 4. Transition — Current Version

**Над чем действует:** над текущей версией объекта с данными.

- Срок `Days After` отсчитывается от создания текущей версии.
- По наступлении срока RustFS переносит **данные этой версии** из исходного HOT-хранилища в указанный tier.
- Версия остаётся **Current**, её ключ и `VersionId` не меняются.
- Локальные метаданные сохраняются; чтение через исходный S3 endpoint направляется к удалённому tier.
- Не создаёт Delete Marker, не переводит версию в Non-current и не задаёт срок её удаления.
- Не переносит прежние версии только потому, что они относятся к тому же ключу.

## 5. Transition — Non-current Version

**Над чем действует:** над прежними версиями объекта с данными.

- Срок `NoncurrentDays` отсчитывается от перехода версии в Non-current.
- По наступлении срока переносит **данные этой старой версии** в указанный tier.
- Текущую версию не затрагивает.
- Delete Markers не переносит: в них нет содержимого объекта.
- Версия сохраняет свой `VersionId` и остаётся доступной для чтения по нему.
- Не удаляет данные логически: версия продолжает существовать, пока её не удалят отдельно.

## 6. Как правила сочетаются

- **Transition** определяет, *где лежат данные версии*. **Expiration** — *когда версия скрывается или удаляется*.
- Оба механизма применяются **к конкретным версиям**, а не ко всей истории ключа сразу.
- Если для одной версии заданы и Transition, и Expiration, срок переноса следует назначать **раньше срока удаления**. В RustFS при одновременной допустимости действий приоритет у Expiration.
- После Current Expiration версия становится Non-current. С этого момента на неё могут действовать **Non-current Transition** и **Non-current Expiration**.
- Перенос версии в COLD **не отменяет** её последующее удаление по Expiration.
- RustFS поддерживает **один первоначальный автоматический Transition каждой версии**; цепочка `HOT → WARM → COLD` через наложение Lifecycle Rules не поддерживается.
- `Prefix` и `Tags` ограничивают круг объектов, на которые распространяется правило; без фильтров правило охватывает бакет. Правило очистки Delete Markers нельзя сочетать с фильтром по тегам.
- Lifecycle выполняет операции **асинхронно**: наступление срока не означает мгновенное завершение действия.

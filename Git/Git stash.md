`git stash` временно сохраняет незакоммиченные изменения и очищает рабочую директорию.

`stash` -- это локальный `commit`, который храниься в директории `.git/logs/refs`.

Это удобно, когда нужно быстро переключиться на другую ветку, но текущие изменения ещё не готовы для публичного коммита.

## Сохранение изменений

```bash
git stash
```

Git сохраняет:

- изменения в отслеживаемых файлах;
    
- изменения, добавленные в индекс через `git add`.
    

После этого рабочая директория возвращается к состоянию последнего коммита.

Добавить описание:

```bash
git stash push -m "Работа над авторизацией"
```

## Просмотр сохранённых stash

```bash
git stash list
```

Пример:

```text
stash@{0}: On main: Работа над авторизацией
stash@{1}: On feature: Незавершённый рефакторинг
```

`stash@{0}` — последнее сохранение.

## Восстановление изменений

```bash
git stash pop
```

Команда:

1. применяет последний stash;
    
2. удаляет его из списка stash.
    

Можно восстановить конкретный stash:

```bash
git stash pop stash@{1}
```

## Разница между `pop` и `apply`

```bash
git stash apply
```

Применяет изменения, но не удаляет stash.

```bash
git stash pop
```

Применяет изменения и удаляет stash.

Поэтому `apply` безопаснее, если нужно сохранить резервную копию изменений.

## Просмотр содержимого stash

Краткая информация:

```bash
git stash show
```

Полный diff:

```bash
git stash show -p
```

Для конкретного stash:

```bash
git stash show -p stash@{1}
```

## Удаление stash

Удалить конкретный stash:

```bash
git stash drop stash@{0}
```

Удалить все stash:

```bash
git stash clear
```

## Неотслеживаемые файлы

По умолчанию `git stash` не сохраняет новые файлы, которые ещё не были добавлены в Git.

Сохранить также неотслеживаемые файлы:

```bash
git stash -u
```

или:

```bash
git stash push --include-untracked
```

## Возможные конфликты

При выполнении:

```bash
git stash pop
```

могут возникнуть конфликты, если текущие файлы сильно отличаются от состояния, в котором был создан stash.

После этого конфликт нужно разрешить вручную, как обычный merge-конфликт.

## Типичный сценарий

```bash
git stash push -m "Незавершённая работа"

git switch main
git pull

git switch feature
git stash pop
```

Итоговая схема:

```text
Незакоммиченные изменения
        ↓
git stash
        ↓
Временное сохранение
        ↓
git stash pop
        ↓
Возврат изменений
```

## Зачем stash несколько родителей

Обычный stash должен сохранить сразу несколько состояний:

1. состояние последнего коммита `HEAD`;
2. состояние индекса — то, что было добавлено через `git add`;
3. состояние рабочей директории — незастейдженные изменения;
4. иногда неотслеживаемые файлы.

Поэтому Git создаёт несколько связанных commit-объектов.

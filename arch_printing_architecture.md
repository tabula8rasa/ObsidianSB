# Архитектура печати HP Ink Tank 310 в Arch Linux

## 1. Что используется

Моя очередь принтера в CUPS:

```text
Ink_Tank_310
```

Принтер подключён по USB.

Основные компоненты:

- **CUPS** — система печати Linux.
- **cupsd** — демон CUPS, который принимает задания, ведёт очередь и запускает обработку печати.
- **cups.service** — systemd-unit демона `cupsd`.
- **cups.socket** — systemd socket unit для активации CUPS при обращении к его сокету.
- **cups.path** — systemd path unit CUPS. Может активировать CUPS при изменениях в каталоге очереди.
- **HPLIP** — набор драйверов и фильтров HP. Для обычной печати отдельный постоянный демон HPLIP не нужен.
- **CUPS USB backend** — компонент, который передаёт подготовленные данные физическому USB-принтеру.
- **lp** — команда отправки документа в CUPS.
- **lpstat** — просмотр принтеров, очередей и состояния CUPS.
- **lpinfo** — просмотр доступных устройств и драйверов.
- **lpoptions** — просмотр и изменение параметров очереди.
- **lpadmin** — создание, изменение и удаление очередей.
- **cancel** — отмена заданий.
- **systemd** — запускает и останавливает CUPS.

---

## 2. Главная схема

```text
PDF / другой документ
        |
        v
       lp
        |
        v
      CUPS
     (cupsd)
        |
        v
очередь Ink_Tank_310
        |
        v
фильтры / драйвер HPLIP
        |
        v
CUPS USB backend
        |
        v
       USB
        |
        v
 HP Ink Tank 310
```

Команда:

```bash
lp file.pdf
```

не записывает PDF напрямую в USB.

Она отправляет задание в CUPS.

---

## 3. Что происходит после `lp file.pdf`

### Шаг 1. Клиент `lp`

`lp` определяет принтер по умолчанию.

Проверить его:

```bash
lpstat -d
```

В моей системе:

```text
system default destination: Ink_Tank_310
```

Поэтому команды равнозначны:

```bash
lp file.pdf
```

```bash
lp -d Ink_Tank_310 file.pdf
```

---

### Шаг 2. Задание получает CUPS

`lp` передаёт задание демону `cupsd`.

CUPS:

- создаёт идентификатор задания;
- помещает задание в очередь `Ink_Tank_310`;
- сохраняет метаданные задания;
- определяет настройки печати;
- запускает необходимые фильтры;
- передаёт конечный поток backend-компоненту принтера.

Пример ответа:

```text
request id is Ink_Tank_310-5 (1 file(s))
```

`Ink_Tank_310-5` — идентификатор задания CUPS.

---

## 4. Что такое очередь `Ink_Tank_310`

В CUPS пользователь работает не напрямую с USB-устройством, а с логической **очередью принтера**.

Имя моей очереди:

```text
Ink_Tank_310
```

Посмотреть очереди:

```bash
lpstat -p
```

Посмотреть принтер по умолчанию:

```bash
lpstat -d
```

Посмотреть всё:

```bash
lpstat -t
```

---

## 5. Как очередь связана с физическим принтером

У очереди есть Device URI.

Посмотреть его:

```bash
lpstat -v
```

Для USB-принтера он имеет вид:

```text
device for Ink_Tank_310: usb://HP/Ink%20Tank%20310%20series?...
```

Этот URI говорит CUPS, куда отправлять готовый поток печати.

То есть:

```text
Ink_Tank_310
      |
      v
usb://HP/Ink Tank 310 series...
      |
      v
физический USB-принтер
```

---

## 6. Роль HPLIP

HPLIP установлен как пакет:

```bash
pacman -Q hplip
```

HPLIP нужен для поддержки конкретного HP-принтера.

Он предоставляет:

- драйверы;
- PPD/описания возможностей принтера;
- фильтры преобразования печатного задания;
- утилиты `hp-*`, включая `hp-setup`.

Для обычной печати HPLIP не обязан иметь постоянно работающий демон.

Основной постоянно работающий процесс печати — `cupsd`.

---

## 7. Зачем нужны фильтры

Принтер не обязан понимать исходный PDF.

Поэтому CUPS и драйвер:

```text
PDF
 |
 v
CUPS filters
 |
 v
формат, подходящий принтеру
 |
 v
USB backend
```

Именно поэтому наличие корректного драйвера имеет значение даже тогда, когда CUPS уже видит устройство по USB.

---

## 8. USB backend

После преобразования задания CUPS выбирает backend по Device URI.

Для:

```text
usb://HP/...
```

используется USB backend CUPS.

Его задача:

- открыть устройство;
- передать подготовленный поток данных;
- вернуть CUPS результат выполнения.

---

## 9. Демон `cupsd`

Проверка:

```bash
systemctl status cups.service
```

или:

```bash
systemctl is-active cups.service
```

`cupsd` отвечает за:

- очереди;
- задания;
- управление принтерами;
- обработку запросов `lp`;
- запуск фильтров;
- запуск backend;
- веб-интерфейс CUPS;
- IPP-интерфейс печати.

---

## 10. `cups.socket`

Проверить:

```bash
systemctl status cups.socket
```

`cups.socket` позволяет systemd ждать подключения к CUPS без необходимости держать `cupsd` запущенным всё время.

Когда клиент обращается к CUPS:

```text
lp
 |
 v
cups.socket
 |
 v
systemd запускает cups.service
 |
 v
cupsd
```

Если `cups.service` уже работает, запрос сразу получает `cupsd`.

---

## 11. `cups.path`

Проверить:

```bash
systemctl status cups.path
```

`cups.path` следит за определёнными файловыми событиями CUPS и также может активировать `cups.service`.

Из-за этого команда:

```bash
sudo systemctl stop cups.service
```

не является полной остановкой всей системы CUPS, если `cups.socket` или `cups.path` продолжают работать.

---

## 12. Какие сокеты использует CUPS

CUPS использует локальный Unix-сокет и может слушать IPP на TCP-порту 631 в зависимости от конфигурации.

Проверить:

```bash
ss -ltnp | grep ':631'
```

и:

```bash
ss -lx | grep cups
```

При активном `cups.socket` listener может существовать даже при остановленном `cups.service`.

---

## 13. Веб-интерфейс

CUPS предоставляет:

```text
http://localhost:631
```

Это интерфейс того же сервера CUPS.

Через него можно:

- просматривать принтеры;
- просматривать задания;
- добавлять и удалять принтеры;
- менять настройки.

Раздел Administration требует системную авторизацию.

---

## 14. Основные команды

### Узнать имя принтера

```bash
lpstat -p
```

### Узнать принтер по умолчанию

```bash
lpstat -d
```

Мой:

```text
Ink_Tank_310
```

### Состояние всей системы

```bash
lpstat -t
```

### Состояние конкретного принтера

```bash
lpstat -p Ink_Tank_310 -l
```

### Device URI

```bash
lpstat -v
```

### Текущая очередь

```bash
lpstat -o
```

### Завершённые задания

```bash
lpstat -W completed -o
```

### Печать

```bash
lp -d Ink_Tank_310 file.pdf
```

### Отмена задания

```bash
cancel Ink_Tank_310-N
```

### Отмена всех заданий пользователя

```bash
cancel -a
```

### Возможности и параметры принтера

```bash
lpoptions -p Ink_Tank_310 -l
```

### Устройства

```bash
lpinfo -v
```

### Только HP

```bash
lpinfo -v | grep -i hp
```

## 15. Где находятся настройки CUPS

Основной каталог:

```text
/etc/cups/
```

Важные файлы:

```text
/etc/cups/cupsd.conf
/etc/cups/cups-files.conf
/etc/cups/printers.conf
```

`printers.conf` содержит конфигурацию очередей.

Обычно эти файлы вручную менять не требуется.

---

## 16. Логи

CUPS запущен через systemd, поэтому журнал смотрится через `journalctl`.

Последние сообщения:

```bash
sudo journalctl -u cups.service -n 100 --no-pager
```

Сообщения с момента загрузки:

```bash
sudo journalctl -u cups.service -b
```

После конкретной попытки печати:

```bash
sudo journalctl -u cups.service --since "5 minutes ago"
```

---

## 17. Что НЕ нужно запускать отдельно

Для обычной USB-печати через текущую конфигурацию не нужно вручную запускать:

- `hp-setup` при каждой печати;
- отдельный демон HPLIP;
- веб-интерфейс;
- браузер;
- `lpinfo`;
- `lpstat`.

`hp-setup` нужен только для настройки или восстановления конфигурации.

---

## 18. Архитектура в одном блоке

```text
                        systemd
                    /      |      \
                   /       |       \
             cups.socket cups.path cups.service
                   \       |       /
                    \      |      /
                         cupsd
                           |
                  очередь Ink_Tank_310
                           |
                  HPLIP / CUPS filters
                           |
                    CUPS USB backend
                           |
                          USB
                           |
                   HP Ink Tank 310
```
